# SOP instance state and implementation projections

`serializeInstanceState` writes one versioned instance with an immutable instance ID, schema identity/version, revision, ordinary typed object facts and explicit local relations. Native/local object IDs are retained separately; their SOP fact IDs are deterministic and do not change when population order changes. Copying to another instance requires an explicit new instance ID. External references and project namespace resolution are not implemented by this local archive.

The descriptor supplies `objects: [{id,type,attributes,relations,metadata?}]` and a finite, acyclic `projection`. Attributes contain ordered literal values. Relations contain actual local object IDs; no literal equal to an ID becomes a reference by guessing. Structured attribute values, metadata and the implementation projection use `sop.instance-state/2`: object and array containers are SOP nodes; their scalar members are direct typed literals. An object node pairs ordered `key` values with ordered `member` values; an array's `member` order is its index order. A nested container is an explicit reference. Arbitrary string keys, literal strings starting with `$`, null, booleans, finite numbers and negative zero round-trip exactly. Only a scalar root needs its own scalar node. Scalars have no separate identity, provenance or variable semantics. There is no opaque JSON snapshot string.

For example, a projection object is `@state.value.0 std.instance.value key="name" key="size" key="outline" member="r1" member=62 member=null kind="object"`. Ordinary semantic facts already use direct attributes such as `x=80`; the codec does not wrap those scalars. The reader also accepts legacy `sop.instance-state/1` archives with separate typed scalar members and explicit indices. New writes use version 2, without deleting any fields or native undo data.

`readInstanceState` reconstructs the descriptor/projection and rejects malformed, cyclic, unowned or excessive data. Unknown formats are refused. The archive is a transport codec, not evidence that a consumer's projection agrees with its facts. A consumer must recreate its declared view and compare it with the saved facts before adopting that tool cache; mismatch leaves the saved instance intact. Schema/version changes require a declared migration rather than silent reinterpretation.

`instanceStateWorld(wires,{schema})` loads the actual saved facts into a World with the caller's ordinary SOP declarations/rules. `factsOf`, matching and deduction see them. The tested example infers which restored node lacks an incoming link using `core.rule`, without a host callback for that decision. This does not implement arbitrary request completion or grant execution authority.

The implementation projection exists for renderers/tools during migration. It is typed data, separate from the facts on which reasoning operates. Storage (files, IndexedDB or another carrier), native bindings and cross-instance project loading belong to the consumer. No storage API, domain name, UI or sentence interpretation is present in this mechanism.


`instanceStateWorld(wires)` validates the complete carrier, then loads only ordinary domain facts and the actual reference closure required by their attributes and relations. It does not load `std.instance.snapshot`, `std.instance.object`, native projection containers, or observation binding metadata into the inference world. Structured domain attributes retain their referenced values; local object cycles remain ordinary relations. `{includeArchive:true}` explicitly loads the entire validated carrier for diagnostic use. This separation does not turn an observation-derived world into the operational authority of a tool.

`instanceStateWorld` loads only ordinary object facts and their referenced structured values/local facts. Projection/history data, `std.instance.object` descriptors and snapshot metadata remain in the carrier. `includeArchive:true` is a diagnostic opt-in. This makes an inference context smaller without asserting that the consumer has made it the operational authority.
