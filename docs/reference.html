Reference: the wire types of the matrix, and the functions

One entry per wire type that the matrix language knows, all in the same shape, then the functions. The grammar of wires is in language.md; how a world behaves as a whole is in semantics.md; the methods are in api.md.

In the syntax tables, rep. means the attribute may be repeated. A flag is true or absent. An attribute that a type does not read is not an error; it is noted in world.warnings (unknown-attribute), because it is usually a misspelling.

Every example on this page is run by the test suite; the output shown is what it prints.

Declaring what may exist

core.slot

One key of one type: what it may hold, and whether it must be there.

Syntax

It stays open while no T fact has the key (a lazy load tells the referring facts first). It is refused when the statement making the reference finds the targets loaded without that value. A reference made earlier that is still open is reported by world.check() as an open-join issue, not refused

Kinds: integer, number (integer or decimal), boolean (true, false), string (quoted), atom (a name), quantity.<name> (a number with a unit), time.<name> (time.clock 10:40, time.date 2026-01-30, any other name: an atom), any, ref (a reference; with to=T, to a wire of type T, and a wire it refers to cannot be retracted while it does), blob and json (below). With several kind and type attributes the value must fit one of them.

Structured values. Under a key whose slot says kind=json the value is a string whose text is JSON (an object, an array or a scalar), at most 10 levels deep and 100,000 characters long. Two values that are the same JSON are the same value, whatever the spelling (the order of keys, spaces): they are compared and indexed in one canonical form. A pattern reads into it with a path after the key: center.lat=?lat, center.tags.0=?first (array items by position; at most 10 names). A number or a boolean at the path is an atom, so 9.190 matches 9.19; a string is a string; an object or array is its canonical JSON as a string; a path that is not there does not match. Templates write the whole value. Why: a structured value (a point, a range, a style) is kept as one value instead of being flattened into keys and a copy as text.

Opaque values. Under a key whose slot says kind=blob the value is kept exactly as given (text given to fill becomes a string value, whatever it contains), it is not put in any index, and no rule or deny can read it: a pattern that names the key is a schema violation, except core.absent=<key>. Two values are the same only when they are equal. It is a value like any other for marks, rewind, undo, forks, snapshots and queries. Why: a large immutable result (an analysis of a document, kilobytes to megabytes) must undo with the rest of the world without costing anything to the rules; in a 600-wire world a 1 MB value costs 3.6 ms to fill, 5.5 ms to tell as text, and nothing to a fork or a mark (node bench/blob.mjs).

Meaning. For every fact of type of or of a type that extends it: each value of key fits a kind or type if any is given, is in enum if given, lies within min and max if given; the key has at most one value unless many; if required, the key is open until it has a value. Under a key whose every kind is integer or number, values are compared as numbers (5 is 5.0). Two facts of the type that agree on all identity keys are the same wire.

When it is evaluated. Validation, at the end of every change, for the wires the change touched; for all wires when the matrix changes. Identity is applied when a wire is told. default, enum, min/max/step and ask are read by completion and search.

Interactions. Inheritance: a slot holds for subtypes; a subtype may declare the key again, and the nearest declaration holds. Two declarations for the same type and key: equal ones are one; different ones are refused unless one says combine=. Tiers: a default is applied as tier default. Soft: see core.issue. Closed types: only declared keys (and keys of an open namespace) are accepted.

Violations. domain (kind, type, enum, bounds), cardinality (several values without many), unknown-key (undeclared key on a closed type), dangling-ref (a reference to a wire that does not exist), conflict (a second, different value told for a single-valued key), schema (bad or conflicting declaration).

Example

Limits. Bounds apply to numbers and quantities only. enum compares text, except under a numeric kind. A range (min, max, step) is a domain only up to 2,000 values.

core.type

A type: what it extends, whether its keys and its instances are all known.

Syntax

AttributeValueDefaultRep.Meaning
oftyperequiredthe type declared
extendstypenoneyesits parent; more extends are slot groups (mixins): their slots and patterns apply too, after the type's own line
closedflagfalsewires of the type accept only declared keys
completeflagfalsethe world knows every wire of the type
transientflagfalsestate that is looked at, not edited (a selection, a cursor): undo passes over it
uniquekeynoneyesno two wires of the type have the same values for these keys together
sharedflagfalseits wires belong to every namespace: matched and merged across them

Meaning. A wire of a type is also a wire of every type its type extends: patterns, slots, rules, denies, effects and queries written for an ancestor apply to it. A type need not be declared to be used; declaring it adds the parent and the two flags. complete changes one answer: asking whether a wire of the type exists is no when none matches, where it would be unknown.

When it is evaluated. When the matrix is compiled; the hierarchy is then part of every index, so matching by an ancestor type costs the same as by the type itself.

Interactions. Slots: inherited, nearest declaration wins. Negation: not= and core.absent= do not need complete; they speak of what the world holds now. Changing the hierarchy re-indexes the facts.

Violations. schema (a type that extends itself, directly or not; a type declared twice with different parents), unknown-key.

Example

Limits. One parent per type.

core.schema.map

How to read slot, type and module declarations that are written in another notation.

Syntax

AttributeValueDefaultRep.Meaning
fromtyperequiredthe type of the foreign wires
asslot | type | moduleslotwhat they declare
one per fieldwhere to find itsee below

Fields for as=slot: owner (the type; default id.prefix), key (default id.suffix), value (kinds and $type references together), kind, type, enum, many, required, id, prefix, default, ask, min, max, step. For as=type: name, extends, closed, complete, transient, shared (each true when the field gives true or yes), unique (keys, repeated or comma-separated), root (a type that every type without a parent extends). For as=module: name, imports.

A field is found by: id (the wire's id), id.prefix (its id up to the last dot), id.suffix (the rest), <attr> (that attribute), <attr>:<value> (true when the attribute has that value).

Meaning. Every wire of type from is read as the declaration it maps to, exactly as if it had been written as a core.slot or core.type wire, and belongs to the matrix.

When it is evaluated. When the matrix is compiled. The mapping must be told before, or with, the wires it maps.

Interactions. Mapped wires may carry any other attributes (no unknown-attribute note). Two different maps for one from are refused.

Violations. schema.

Example

Limits. One wire per declaration; a notation that spreads a slot over several wires cannot be mapped.

core.use

Load a matrix from the library.

Syntax

AttributeValueDefaultRep.Meaning
worldmodule namerequiredyesthe module, a key of new World({ library })
prefixfalseprefixedload the ids as written
asnamethe module nameload the module under another name: its own prefix (list.) becomes this one (tasks.) in its ids, types and references

Meaning. The text kept in the library under that name is told as part of the same change. Unless prefix=false, every id it declares, and every reference among them, gets the module name and a dot in front, so two modules cannot clash. A module is loaded once per world, and once per as name: core.use world=list as=tasks and core.use world=list as=shopping give two worlds of one module (words are told after loading, as core.word wires). world.use(name) is the same as telling this wire.

Interactions. A module may contain core.use wires. The composition rules for slots and types apply across modules. A module declares types and slots only under its own name, and may limit what others read (core.module).

Violations. schema (no such module); whatever the module's own wires raise.

Example

Limits. A module cannot be unloaded.

core.module

A module that names itself: what it imports and what other modules may read.

Syntax

AttributeValueDefaultRep.Meaning
namenamethe wire's idthe module, and the prefix of its types
versiontextnonea label for the module's version, reported by world.modules(); nothing checks it
importsmodule namenoneyesmodules of the library loaded with it, ids unchanged
exportstypeall its typesyesthe types other modules may read (item means <name>.item)

Meaning. A module loaded from the library (by core.use or imports) may declare types and slots only under its own prefix: shop declares shop.item, not item and not geo.place. With exports, a rule or deny of another module may read only those types (and their subtypes) of this module. world.modules() lists the modules with their version. After modules are joined, a short key that two modules declare along one type's lineage is reported in world.warnings (ambiguous-key, with both qualified names). The same can be declared through a core.schema.map with as=module (its exports field).

When it is evaluated. When the matrix is compiled.

Interactions. Modules without exports: every type is readable, as before. Rules outside any module (the host's own matrix) read everything. Facts are not in modules; they may be in namespaces.

Violations. schema (a type or slot outside the module's prefix, naming the module and the type; a rule that reads a type another module does not export, naming both modules; a module declared twice with other imports; an import that is not in the library). duplicate-id for a matrix id declared twice, naming both owners (the application or a module); an import whose own declaration lost such a clash says so, with the ids.

Example

Limits. Exports name types, not keys. A version is a label: imports do not ask for one.

Saying what follows and what cannot be

core.rule

If the patterns match, the templates hold.

Syntax

AttributeValueDefaultRep.Meaning
when$patternat least oneyespatterns that must all match
not$patternnoneyespatterns that must have no match
with$calcnoneyesvalues to compute, in order
if$checknoneyesconditions that must all hold
then$templateat least oneyeswhat then exists
lazyflagfalsemade only when a question, a check or a deny needs it (below); only for structures rarely asked, since each question pays for all lazy rules

Meaning. For every way of matching all when patterns at once (a variable has one value throughout; $p in one pattern is the wire another pattern @p matched), such that no not pattern matches under the same bindings, every with calc has a result and every if check holds: each template, with the variables replaced, exists. A template with core.on=$p adds its entries to the wire @p matched. Any other template names a wire: if a fact has the same identity keys, or already has every entry the template gives, it is that fact (and gets any entries it lacks); otherwise a new fact is made. An entry whose variable has no value is left out.

When it is evaluated. In the chase, after every change, to a fixpoint: for the wires that were added or changed, and again in full for rules with not=, a selector, core.absent= or an aggregate when a type they read changed. What a rule concluded is withdrawn when one of the wires it read goes or changes.

Interactions. Negation must be stratified: a rule may not negate or aggregate what its own conclusions can produce (a core.on= template counts only against patterns that name a key it sets). Depth: a wire derived from derived wires more than maxDepth (12) deep is refused. Tiers: a conclusion is as weak as the weakest value it was read from. Provenance: via is the rule, from the matched wires, cells the values read. Identity: a derived wire has an id made from the rule and the bindings.

Violations. schema (names something that is not in the matrix; no when or no then; not stratified; a variable in a template that no pattern binds and no calc computes; an unknown function), depth, conflict (the conclusion contradicts a value that is there).

Example

Lazy rules. With lazy=true a rule is not run when the world changes. ask, query and check() run the lazy rules first (to a fixpoint, in a transaction that is then undone), so they answer as if the rules were eager; a deny that reads what lazy rules make does the same whenever something it or those rules read has changed. What a lazy rule makes never stays in the world (get, ofType, toSOP do not see it). A rule that is not lazy may not read what a lazy rule makes (schema). Why: a structure that many changes would re-derive but few questions read (lines of attack on a board) should cost when it is read. The cost moves to the questions: in node bench/lazy.mjs (800 lines from 200 pieces) a turn costs 0.01 ms instead of 0.9 ms, and a question 8.8 ms instead of 0.04 ms, because all lazy rules run for each question; it pays when questions are rarer than about one in ten changes, and not when a deny reads the lazy output on every change.

Limits. No recursion through negation. A rule fires once per distinct set of bindings.

core.deny

The patterns must not match.

Syntax

AttributeValueDefaultRep.Meaning
when, not, with, ifas in core.ruleyes
whystringnonethe reason; ?v writes a variable's value, ?v:f writes it through the registered filter f
softflagfalserecord an issue instead of refusing
prioritynumbernonewhen one change breaks several denies, the lower number is reported first

Meaning. No change may leave the world in a state where the body matches. A change that would is refused as a whole, with why (variables replaced by their values) and the wires that matched. With soft=true nothing is refused: see core.issue.

When it is evaluated. Validation, at the end of every change, after the chase: from the wires the change touched; in full for denies with not=, a selector or core.absent=, and when the matrix changes.

Interactions. Search: denies without negation, selectors, aggregates or computed values are turned into ruled-out combinations for the solvers; the others are checked when a whole assignment is verified. States: a deny over a fluent is checked when an event changes it, so the event is what is refused.

Violations. deny, with rule, why, bindings (every variable and matched wire, as tokens), vars (the variables as data: strings as their text, plain numbers as numbers, no wire ids), wires, support, involved.

Filters. In why, ?n:ordinal writes the value of ?n through the filter ordinal, which the host registers (a variable with several values, from collect or ties=all, reaches the filter as one list, and vars holds it as a list; written without a filter, its values are joined with ", ") (new World({ filters }) or world.register('filter', name, fn); fn(value, { world, name }) returns the text). No filter is built in, so the core holds no language: a host registers the ones of its own. A filter that is not registered is a schema violation of the deny. A colon not followed by a name is text (?n: too many).

Example

Limits. A deny says what must not be; to require that something exists, use a required slot or a rule.

core.calc

A value computed by a function, inside a rule, deny or action.

Syntax

AttributeValueDefaultRep.Meaning
out?variablerequiredthe variable that gets the result
fnfunction namerequireda function, or with over= an aggregate
argsvalue or ?variablenoneyesthe arguments, in order
over$patternnoneyesmakes it an aggregate over the matches of these patterns
pick?variablenonefor argmax/argmin: what to return for the best match
tiesfirst | allreport tiesfor argmax/argmin: first takes the first of equals silently; all gives every one of them, as several values

Meaning. After the patterns matched, out is bound to fn(args). If a function has no result (an argument without a value, a division by zero, units that differ) the rule does not fire for those bindings. Calcs are computed in the order of the with= attributes; a later one may use the out of an earlier one.

When it is evaluated. Each time its rule's body is evaluated.

Interactions. Precision: results are rounded as core.precision says. Abduction can run add, sub, mul, div backwards. Queries: a function may say why it has no result (world.cannot), and the query answers unsupported.

Violations. schema (unknown function, no out).

Example

Limits. A function sees only its arguments and the world; it must not change the world.

core.aggregate

One aggregate over every match of some patterns, with no wire to anchor it: a total, a count per kind, the longest of something.

Syntax

AttributeValueDefaultRep.Meaning
over$patternrequiredyesthe patterns it ranges over
count, sum, min, max, argmin, argmax, collect?variablethe result, by the name of its aggregate: count=?c
fnaggregate nameinstead: the aggregate, with out
out?variablewith fn: the variable that gets the result
args?variablenonethe value taken from each match (for all but count)
pick?variablefor argmax/argmin: what to return for the best match
tiesfirst | allreport tiesas on core.calc
by?variablenoneyesone result per value of these variables among the matches
groupsvalue | $patternnoneyeswith one by variable: groups that always have a result, members or not (a value, or every wire the pattern matches, as $id)
defaultvaluenonethe result when there is nothing to aggregate (and for a declared group with no member)
then$templateyeswhat holds, with the result (and the by variables)

Meaning. Without by: exactly one result exists at all times, computed over every match of the over patterns; over no match, count and sum give 0 and the others give default (or nothing, and then the templates do not hold). With by: one result for each distinct value of the by variables among the matches; a value that no match has any more has no result. With groups=, every declared group has a result as well: an empty one gets count 0, or default when given; a group named by a pattern comes and goes with the wires the pattern matches. The templates hold with the result, like the conclusion of a rule.

When it is evaluated. In the chase, with the other aggregates: when the matrix changes, and for the groups whose wires arrive, change or go (and, with groups=$pattern, for a group wire that arrives or goes).

Interactions. Distinct anchors: by= is the way to compute something once per distinct value: a rule anchored on a member computes it once per member (2,000 members in 50 groups: 238 ms against 15 ms, node bench/distinct.mjs). Withdrawal: when the result changes, the old conclusion is withdrawn and the new one made. Identity: the templates of two aggregates should differ in type or in a key, since a template that has every entry of an existing wire is that wire. Stratification: an aggregate may not range over what its own templates produce. Namespaces: a result is in the namespace of the wires it counts, in the default one when they span several (SC5a). Provenance: via is the aggregate's id.

Violations. schema (no result, both fn= and a result name, no over, a by variable that no over pattern has, a pattern that names a blob key, groups= without exactly one by variable).

Example

Limits. One aggregate per wire; for several results over the same patterns, write several aggregates, or a rule with several calcs. With no anchor it ranges over every namespace; to count within one, aggregate in a rule anchored on a wire of that namespace.

core.rank

The position of a wire among its peers, ordered by a key: "the 2nd chapter".

Syntax

AttributeValueDefaultRep.Meaning
of$patternrequiredone of the rule's when= patterns: the wire whose position is wanted
bykeyrequiredthe key that orders the peers
out?variablerequiredgets the position, from 1
orderasc | descascsmallest first, or largest first
within?variablenoneyespeers share the value of these variables of the pattern

It is named in a rule's with=, like a core.calc.

Meaning. The peers of the wire of matched are the wires that fit the pattern's fixed values (and, with within, share the values of those variables); every other variable of the pattern is free. They are ordered by the value of by, as numbers when both values are numbers, else as times or as text; equal values keep the order of the sequence. out is the position of the wire among them.

When it is evaluated. With its rule. It is an aggregate over the peers, so when a peer arrives, changes or goes, the positions of its group are computed again.

Interactions. As for aggregates: kept up to date, withdrawn and remade when the position changes; a rule may not rank what its own conclusions produce.

Violations. schema (of is not a when= pattern of the rule, no by, an order other than asc or desc, a within variable the pattern does not have).

Example

Limits. One key orders the peers; to order by two keys, derive a key that combines them.

core.relation

A linear relation among values, from which whichever one is missing is computed.

Syntax

AttributeValueDefaultRep.Meaning
when$patternat least oneyespatterns whose entries bind the variables
sum?v or <n>*?vyesa term added
sub?v or <n>*?vyesa term subtracted
equalsnumber0the constant

Meaning. Wherever the patterns match, the sum of the sum terms minus the sub terms equals equals. Each variable stands for one value of a matched wire (a cell). After the known cells are put in: if none is unknown and the relation does not hold, the change is refused; if exactly one is unknown, its value is computed, exactly, and put on its wire; if several are unknown, nothing happens yet.

When it is evaluated. In the chase, like a rule: it is compiled into one rule per cell.

Interactions. Tiers: a computed value is as weak as its weakest input. Slots: the computed value must fit the cell's slot (an integer cell does not take a half). Units: all values must have one unit, which the result takes. Search: relations conclude only what one relation forces; trying values against each other is left to the search. Abduction goes through relations. relation=true on a core.calc with fn=add or fn=sub makes that calc such a relation over the cells of its rule.

Violations. conflict (the relation does not hold), domain (the value does not fit), schema (a variable that is not the value of a key in the patterns).

Example

Limits. Linear only. A result whose decimal does not end is written with 12 significant digits. A variable that names the same cell in two patterns is read, never solved for.

Patterns and templates

Three attributes are read on patterns and templates of any type and are not part of the wire described.

AttributeOnValueMeaning
core.absentpatternkey, rep.matches only a wire that has no value for that key
core.selectpatternlatest | firstof the wires that fit the bindings made so far, only the latest (first) in the sequence
core.ontemplate$patternadd the template's entries to the wire that pattern matched

Meaning. As in the table. What a rule concluded from an absence or a selection is withdrawn when the key is filled, or a later wire arrives.

Joining by reference. A value $p in a pattern is the wire that pattern p matched: @rm room w=?rw and @pin piece in=$rm x=?x match a room and the pieces whose in refers to it (the order of when= gives the order of the join). There is no attribute for the id of a matched wire: a reference is the join.

When it is evaluated. With the rule. A rule whose only selection is core.absent on its own patterns is driven by the wires it matches, like any rule: a match that a key coming ends is taken back there. Rules that use core.select, and denies with core.absent, are re-evaluated in full when a type they read changes.

Interactions. A rule may not fill a key that it requires to be absent (schema). With either of the two pattern attributes in the matrix, the search stops trying values one at a time (semantics).

Example

Limits. core.select orders by the sequence only.

Time and state

core.sequence

Which key carries the place of a wire in time.

Syntax

AttributeValueDefaultRep.Meaning
keynamerequireda key whose numeric value is the wire's place

Meaning. Wires are ordered by the value of that key; a wire without it takes the place of the last wire that had one; ties are broken by arrival. Without this declaration the order is the order of arrival. The order is what before, after, core.select, fluents and asOf use.

When it is evaluated. When a wire is told. If the key is declared later, the wires already there are given their places again.

Violations. None of its own.

Limits. One sequence per world; of two declarations the one compiled last holds.

core.fluent

A key whose value is a state that events change.

Syntax

AttributeValueDefaultRep.Meaning
oftyperequiredthe type that has the state
keynamerequiredthe key that holds it
deltanamenonea second key that holds the known change since the last statement
bynamenoneyeskeys that identify the holder (informative)

Meaning. The value of the key on a wire is: the last value stated for it (told with the wire, or filled later), then every effect of the events after that statement, in sequence order. A value told for the key of an existing wire is a new statement, not a conflict. Without any statement the state is unknown, whatever the events; with delta, the sum of the add and sub effects since the last statement is kept under that key even then.

When it is evaluated. In the chase, when a holder or an event that affects it is added, changed or removed.

Interactions. Slots: the state must stay within the slot's bounds, or the event is refused; soft=true on the slot keeps the event and records an issue. Retraction of an event recomputes the state. As-of gives the state at an earlier place. Tiers: the state is as weak as the weakest of its events and its statement.

Violations. conflict (an effect would break the slot's bounds, or cannot be computed), schema.

Example

Limits. One state per key; a state is a single value.

core.effect

How one type of event changes one fluent.

Syntax

AttributeValueDefaultRep.Meaning

std.turn: the request pipeline as data

core.use world=std.turn; run by turnFlow. A stage: std.turn.stage name= after= before= per=candidate on_empty= skip_if= only= when=exhausted; a provider: std.turn.provider stage= name= tier=. The order is the after chain from the stage that follows nothing (equal places by name); a stage with before= goes right before that one. Stages with per=candidate run for each candidate reading in turn; when one yields nothing, on_empty says what follows: next (the next candidate), ask (return the question it set), fail. skip_if=<key>: skipped when a request of the candidate has that argument (the message named the world, say); only=<action>: run only for those actions. when=exhausted: run when no candidate was taken (the graded fallback). Providers of one stage are tried by tier: the first that yields wins; a reader's candidates add up. The default: read (given) → dryrun → apply → reply per candidate; fallback when exhausted. Advice: a stage nobody provides, or placed after or before an undeclared stage, is a soft issue (world.check().issues). Fixed: apply is one sentence (one undo step, all or nothing), budgets per call, the same input and state give the same path, a trace of every stage taken.

Text

A string argument is read as its text, an atom as it is. A text result is a number when it is one (so that it compares as one), else a string.

FunctionArgumentsResultNo result when
matchestext, pattern, [n]in a check: whether the pattern matches somewhere in the text; in a calc: the match, or its n-th groupno match; a pattern that is refused (below); a text longer than 100,000 characters

A pattern is a JavaScript regular expression (with the u flag) of at most 200 characters, without back-references, and without a repeated group that can itself repeat or match nothing ((a+)+, (a*)*, (a?)+, (|a)+): those are the shapes whose matching can take exponential time. The rule is conservative: (?:x+y)*, which is safe, is refused too; write (?:x+y)(?:x+y)* or rephrase. A pattern written in the matrix is checked when the matrix is read (schema); one that comes from a wire is checked when it is used, and a query that needed it answers unsupported with the reason. The names are written like the other built-ins (time_add), hence starts_with.

Used with over= on a core.calc. The calc ranges over every match of the over patterns under the bindings of the rule so far; args gives the value taken from each match.

An aggregate is kept up to date: when a wire it ranges over arrives, changes or goes, the groups it belongs to are computed again. A rule may not aggregate over what its own conclusions produce.
