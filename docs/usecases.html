Use cases

Seven ways to put a world to work. Each one names the pattern, shows the calls, and says what you still need around the library.

1. Logical completion in a chat

Pattern. A formaliser turns each user turn into incomplete wires. The world decides what follows, what was only assumed, what must be asked and what is impossible. One call per turn.

You bring. The step from text to wires (an LLM, or a reader such as VSS) and the step from question wires back to text. The world guarantees that whatever is generated is consistent.

2. Digital twin of a device or process

Pattern. One wire per current reading, identified by what it measures. A new reading replaces the old one in one transaction. Alarms and derived states are rules; impossible states are denies. A listener forwards committed changes.

You bring. Transport and timing. The world has no clock: time is a value you put on wires.

3. Procedures and workflows

Pattern. Steps are facts linked by after=. What is ready next is a rule with negation ("the previous step is done and this one is not"). Doing a step early is a deny. Undoing a step is a retraction.

The same matrix serves any procedure: the steps are data. This is the shape of an SOP executed by an agent, with the world as the record of what was done and what may be done next.

4. Diagnosis and explanation

Pattern. Rules run from causes to effects. Mark the causes as abducible, then ask for explanations of what was observed. Each explanation can be adopted, which predicts the other effects, or checked by asking for one more observation.

You bring. Costs or a rank function if some causes are more likely than others. The world says what is possible, not what is probable.

5. Building a matrix from examples

Pattern. Collect example circuits, induce slots and rules, review the text, tell it to a world. The world is the safety net: a learned rule that contradicts what is already there is refused, with the deny that it hit.

You bring. Clean, grouped examples. Induction here is exact generalisation, without statistics.

6. Composing knowledge units

Pattern. Each micro-world is a matrix in a library. A world loads the ones it needs with core.use; their wires get the module name as an id prefix. Modules meet through shared types or through bridge rules.

Abduction, completion and retraction work across modules without extra code, because after loading there is one matrix.

7. Scheduling and configuration

Pattern. Many open keys with closed domains and constraints between them: rooms and times, parts of a configuration, shifts. Ask for one full solution, or let the world commit one as assumptions that later statements can still replace.

The search strategy is chosen when the world is created. See Solvers for the built-in ones and for clingo and SAT solvers from outside.
