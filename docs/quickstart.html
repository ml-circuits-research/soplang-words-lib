Quickstart: a new application in an hour

A small room planner: a world schema, three acts, a knowledge world read by lookup, replies, and one request handled end to end: by the last step it is a live world (the three kinds are in the glossary, and what each may contain in kinds of worlds). Every block on this page runs in CI against the library. A page about what each job can do is capabilities; what a host supplies is the host contract.

1. Install and load

Zero dependencies: npm install sopworld, or copy docs/sopworld.mjs (one file, Node and browsers). import { World, turn, createCatalog, bundleReader } from 'sopworld';

2. Describe the world as data

A world that does things is a schema: kinds are types that extend std.schema.thing, attributes are slots, and one wire per kind says which acts apply. Nothing else: the acts come from std.acts.

3. Three acts

make, change, ask (and the others) work on any schema. Each returns its difference and is one undo step; a refusal says what is allowed.

4. Knowledge by lookup

The furniture comes from a knowledge catalog: the host says how to read a path (a file, fetch, a bundle); the catalog tells the shards a word needs, schemas first. Here a two-file bundle stands in for sop-knowledge-worlds.

5. One request end to end, with a reply

The host reads text into candidate readings (its job); turn tries them, applies the first the world takes, and gives the replies; when none fits it falls back to one question, "not here but there", or a named guess.

6. Next

  • Test the schema: schemaGrid(world) runs every world × kind × act case; gridTests writes a test file from it; node tools/validate.mjs <files> in one command.
  • Share things between views, teach facts, keep a dialogue's focus, relate things: capabilities.
  • Every standard module: modules. How worlds combine: patterns.
