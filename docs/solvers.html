Solvers

Filling many open keys at once is a search problem. The world states the problem in a neutral form and a solver, chosen when the world is created, searches it. The world verifies every answer.

The problem in neutral form

PartWhat it is
VariablesOne per open key with a closed domain (enum, wires of a type, or a stepped range). The domain holds the values the world accepts one at a time
NogoodsCombinations of values that a deny rules out. All candidate values are put on their wires at once and each deny is matched once; every match names the values it used
OracleThe world itself: push and pop one value, or verify a whole assignment. A refusal names the variables that caused it

Choosing a solver

SolverRunsHow it worksUse it when
solvers.cdcl()Node and browsersNogoods and "exactly one value per key" become clauses for a built-in clause-learning SAT solver. The world verifies complete answers; a refusal becomes one more clauseAlways, unless you have a reason not to. It is the default
solvers.backtrack()Node and browsersDepth-first, smallest live domain first, every step checked by the world. No grounding, no memoryTiny problems, or as a reference when testing another solver
solvers.clingo({ exec })Wherever clingo runsThe neutral problem as an answer set programYou already run clingo, or want its optimisation and enumeration next
solvers.dimacs({ exec })Wherever a SAT solver runsThe neutral problem as DIMACS CNFYou want an industrial SAT solver
solvers.external({ run })AnywhereYou receive the neutral problem and return one value per variableAny other engine: CP-SAT, MiniZinc, a service

A WebAssembly solver answers with a promise. Return the promise from exec or run and use solveAsync; the rest of the API stays synchronous.

The asynchronous path is tested with a stand-in solver in Node and in Chrome. It has not been run against a real WebAssembly build of clingo.

What the world guarantees

  • No wrong answers. An assignment is returned only after the world has applied it in a scratch transaction without a violation.
  • Refusals teach. When the world refuses a proposal, the values that caused it are sent back as a nogood and the solver is asked again. A test feeds the library a solver that ignores the constraints on its first answer and checks that the final answer is right.
  • Three outcomes. sat, unsat, or unknown when the budget ran out. Completion treats unknown as "still possible".
  • Nothing changes. Solving leaves the world as it was. apply or complete({ choose: true }) commit.

Writing a solver

Sat, the clause-learning solver itself, is exported too and can be used on its own: new Sat(n), addClause([1, -2]), solve(budget), model().
