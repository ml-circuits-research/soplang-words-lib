What the library can do

By job, not by API. Each job has a paragraph, an example that runs (every example on this page is run in CI and must print what is shown), the module and the version it came in, and its limits. Where a job is not done yet, it says so. API details: api, reference; how worlds combine: reuse.

Describe a world

Kinds of things are types; their attributes are slots with kinds, value lists, ranges, defaults and questions to ask when they are missing. Everything told is checked against them at once. Core, since 0.1. Limits: one value per key unless the slot says many; a missing required key is an open question, not a refusal.

State facts and rules

Rules derive wires from wires; a conclusion goes when what it rests on goes. Denies refuse a change that breaks them; soft denies only advise. Core, since 0.1. Limits: no rule may negate or aggregate what its own conclusions produce (stratified).

Ask and explain

query answers with a status (yes, no, unknown, supported, ...) and what the answer rests on; why gives the chain behind a wire or a value, back to what was told (the rule, the act, the tier, the source). query since 0.1, why since 0.17.

Act, undo, groups

Actions change the world in one transaction (declared in SOP Lang, or a host function); several requests of one sentence go together or not at all and are one undo step; every action returns its difference. act since 0.5, sentences and diff since 0.17–0.18. Limits: undo does not bring back a retraction (take a mark()).

Worlds that do things, as data; refuse with alternatives

A world is a schema (std.schema): kinds, attributes, which acts apply. The acts (std.acts: make, remove, change, place, connect, group, pick, ask, copy, send, save, load, undo, redo, show, teach, forget) are the same everywhere; a new world needs no rule. A refusal says what is allowed and where. 0.18–0.22. Limits: place writes a position key; relations are std.relations' job.

Fill gaps from other worlds

When a request leaves a key out, other modules offer values in named tiers (std.fill: user, focus, scene, taught, knowledge, default); the best tier wins, the source is kept, a tie is advice. std.know offers from a knowledge catalog. 0.17, 0.19, 0.21.

Keep focus in a dialogue

std.focus keeps what a dialogue is about after each turn (thing, action, place, world); a request that leaves out its thing or action is completed from the turn before, and earlier turns keep theirs. 0.17. Limits: a value chosen by std.fill is not a mention.

Relate and place things

std.relations: on, in, next to, above, in front of, kept: when the other thing moves, the place follows; rows; the first; one per place. std.boxes has the geometry functions. 0.16–0.17. Limits: boxes only; a row assumes equal widths.

Share things between views; teach facts

Several views read the same things; a view shows some aspects; showing a thing that lacks one is refused with the reason. Facts the user teaches sit at their own tier and say who taught them. 0.21. Limits: one value per key for all views; defaults learnt later do not reach things already made.

Generate cards, examples, replies

From a schema: the card of a world (kinds, attributes, acts, words), example sentences per act with their requests, and the plain-English reply for a done act or a refusal. 0.19. Limits: English only (hosts translate); no coverage grid yet (Round 24).

Drop readings the present state would refuse

score judges candidate readings of one sentence without applying anything: which would be refused and why, which lack something and what to ask. 0.13, cost per reading 0.17.

Measure reuse

tools/reuse.mjs finds candidates for shared modules across worlds (types and rules of the same shape, shared words, parameterised worlds) and a reuse number per world; the option advise gives the same advice to an author at load. 0.21–0.22.
