The language

SOP Lang as sopworld reads and writes it. This file is normative: where another document disagrees with it, this one holds. It is written so that it can be adopted as it stands as the definition of the language (for PSys2: SOP Lang v1.1).

One language serves for facts, for the consistency matrix and for queries. What differs is what a wire is used for, never how it is written.

1. Grammar

Tokens are separated by white space. A token is a run of characters without white space, except that a string may contain white space between its quotes. A token that starts with @ starts a declaration; a token that starts with # starts a comment; any other token must be an entry. The first = of an entry separates key and value.

  1. A declaration starts with @id, continues with a type, and goes on until the next token that starts with @, or the end of the text. It may span any number of lines. Indentation has no meaning. An @ anywhere else (inside a string, or inside an atom: mail=ann@example.org) is text.
  2. An identifier is one or more segments joined by single dots: b1, kids.arith.holding, pat.kids.shop.price.q.2. Letters are the ASCII letters. The first segment starts with a letter or _; a later one may also start with a digit. a..b, a. and 1a are not identifiers.
  3. An entry is key=value, with nothing around the =. The same key may be given several times: the key then has several values, in the order written.
  4. A string uses the escapes of JSON, and no others. A line end, a tab or any other character may also stand in a string as it is. A string is a whole value: it starts right after the = and the token ends at its closing quote.
  5. An atom is any other value. It may contain any character except white space, " and \, and it may not start with $, ?, @ or #; so 10N/kg, 10:40, -4, a=b, #fff after a = (colour=#fff) and 2*?x are atoms.
  6. A comment starts with # where a token could start, and runs to the end of the line. A # inside a string or inside a token is text.
  7. There is nothing else: no nesting, no lists, no operators, no escapes outside strings.

2. The three signs

SignMeaningWhere it may stand
@declares a wirefirst character of a declaration; nowhere else
$refers to a wire, by idfirst character of a value
?is a variablefirst character of a value, in the matrix and in queries

Each sign has one meaning. In particular ? never starts a declaration: @p purchase qty=?q declares a wire named p whose qty is the variable ?q.

Two forms combine them in value position, inside rules only:

FormMeaning
$p where p is a pattern or template of the same rulethe wire that @p matched, or made
$?xa reference to the wire whose id the variable ?x holds

3. Values

A value is never interpreted when it is read. 5 and 5.0 are different tokens; they are the same value only under a key whose slot is declared integer or number.

The canonical spelling of a string is what JSON.stringify writes for its text: \" and \\; \b, \f, \n, \r, \t and \u00XX for the other characters below U+0020; every other character as it is. parse stores every string in this spelling, whatever escapes the text used, so that one text is one value: "café" and "café" are the same value, and a line end written inside a string is stored as \n.

The wire in memory is { id, type, attrs }, where attrs maps each key to the array of its value tokens in the order written: { id: 'b1', type: 'body', attrs: { mass: ['2kg'], tag: ['red', 'round'] } }. A host that parses with its own parser hands over wires of this shape. readValue(token) gives a value as data and writeValue({ kind, v }) gives the token, so a parser that keeps values as { kind, v } converts with one call per value. Wires that do not come from parse are not checked against the grammar; the host's parser is trusted to have done that.

4. What a wire is

A wire is either a fact or part of the matrix. The matrix is the set of wires that say what facts may exist and what follows from them.

  1. A wire is part of the matrix when - its type is a matrix type (core.slot, core.type, core.rule, core.deny, core.calc, core.check, core.relation, core.abducible, core.sequence, core.fluent, core.effect, core.producer, core.action, core.tier, core.precision, core.namespace, core.use, core.schema.map), or - a core.schema.map wire declares its type to be schema, or - a rule, deny, calc, relation or action in the same text names it, through when=, not=, then=, with=, if=, over=, set=, add= or remove=.
  2. A wire named through when=, not=, over= or remove= is a pattern: a description of wires to find. A wire named through then=, set= or add= is a template: a description of a wire to make or to complete. It is one or the other because of where it is named. A pattern needs no variable.
  3. Every other wire is a fact.
  4. A fact may not contain a variable. A wire with a variable that nothing names is refused (variable).
  5. A rule and the wires it names are told together, in one text. A wire that has the id of a pattern and is told later on its own is a fact.
  6. Host functions are declared in the matrix (core.function name=… out.kind=… pure=… with one core.function.arg of=$f name=… kind=… per argument, see the reference); the code itself is the host's, registered with world.register. Only matrix wires call functions: a fact that names fn= is refused. No code goes inside a wire.
  7. Words (core.word text=… means=… of=…, see the reference) are facts. SOP Lang knows no natural languages: the words of a world are in the one language its matrix is written in, and translation is done by the host, outside the world.

5. Ids

  1. Facts and matrix wires have separate id spaces. A fact @p and a pattern @p do not clash. Within one text an id is declared once (section 9), so the two are told in different texts.
  2. Within each space an id is declared once. Telling a fact whose id exists is refused (duplicate-id), unless the new declaration says nothing that the wire does not already say, in which case it is accepted and changes nothing.
  3. A reference $id in a fact must name an existing fact (dangling-ref), except under a key of an open namespace that no slot declares (section 6).
  4. A wire may get a second id: when a fact is told that has the same identity keys as an existing one, it is merged into it and its id becomes an alias (world.resolve(id)).
  5. A matrix loaded as a module with a prefix has its ids, and the references among them, prefixed with the module name and a dot (reference).

6. Keys

  1. A key is a name. Dots have no meaning to the parser.
  2. Short and qualified keys. A key may be written with the type it belongs to in front: on a wire of type shop.order, shop.order.total and total are the same key, and so is <ancestor type>.total. In memory the short form is kept.
  3. Open namespaces. Keys that start with core. are bookkeeping (source, sequence number, provenance). They are accepted on every wire, also of a closed type. Unless a slot declares such a key, its values are not validated, a reference under it need not resolve, and it takes every value it is given. @n core.namespace prefix=audit. open=true declares another such prefix.
  4. Modifiers. Three keys of the core. namespace are read on patterns and templates and are not part of the wire described: core.select, core.absent (patterns) and core.on (templates). See the reference.

7. Queries

A query is one or more patterns. In a query, and only there, a declaration may leave out its @id.

Each match gives one object: the value of every variable under its name, and the id of the matched wire under the id of its pattern, when the pattern has one.

8. Writing wires, and the canonical form

format(wire) writes a wire on one line: @id type and then each entry as key=value, keys in the order they were first given, the values of a repeated key in order, single spaces between tokens. format(wire, { multiline: true }) puts each entry on its own line, indented by four spaces. parse(format(w)) gives w again.

The canonical form is for hashing and for stable diffs: the same wires give the same bytes. format(wire, { canonical: true }) writes @id type, then one entry per line, indented by four spaces, sorted by key (by UTF-16 code unit, as JavaScript compares strings); the values of a repeated key keep their order; strings are in the canonical spelling; atoms, references and variables are written as they are. serialize(wires, { canonical: true }) writes the wires in the order given, each followed by one line end (\n); so the text ends with a line end and has no blank lines.

9. Errors

A text that does not follow the grammar throws SopError. Nothing is repaired silently. The whole text is read, so that one error reports every mistake in it: errors is the list, in the order of the text, each { message, offset, line, column } with line and column counted from 1 and offset from 0, at the start of the token concerned. The error's own message, line, column and offset are those of the first.

MessageCause

invalid identifier in the reference $... / in the variable ?...a $ or ? that is not followed by an identifier
expected key=value, got "..."a token after the type that has no =, or nothing before it

a bad escape in the string of "k" (the escapes are those of JSON)a backslash followed by anything else, or \u without four hex digits

a quote inside an atom (a string value starts right after "=")k=a"b"
a backslash outside a stringk=a\b
the id "x" is declared twice in this texttwo declarations with one id in one text

parse(text, { lenient: true }) accepts what versions before 0.6.1 accepted: the same id twice in one text, an escape that JSON does not have (it stands for the character after the backslash), a quote or a backslash inside an atom. It is for reading old files; world.tell(text) is always strict.

Everything else that can be wrong with a text (an unknown reference, a value of the wrong kind, a rule that names nothing) is not a syntax error: the text is read, and the world refuses the change with a violation (semantics).

10. The old way to declare a pattern

Before version 0.6 a pattern was declared ?id type .... That gave ? two meanings. The old form is still read; such a wire is noted once in world.warnings ({ kind: 'deprecated', id, why }) and is written back as @id. It will be removed in the next minor version. node tools/migrate-syntax.mjs <files> rewrites files, including wires inside the strings of a program.

What v1.1 excludes that v1 allows: an atom that starts with ? (it is a variable now) or with # right after white space (it is a comment; after = it is text). Neither occurs in the v1 corpus of PSys2 (compat/psys2), which the tests read with this parser.

The parser never resolves keys or references and never looks at types: short and qualified keys (section 6), kinds, cardinality and identity are the matrix's business.

12. Scope

What a name means depends on where it is written. Each statement below is checked by the test it names.

SC1. A rule, a deny, an action. Its variables are its own: ?x in one rule and ?x in another are two variables. Inside it, $p names the wire its pattern @p matched (or its template @p made). Test: scope: a variable is local to its rule or question; the same name elsewhere is another variable

SC2. A question. ask and query have their own variables too; a pattern without an id (item n=?x) gets one only the question sees. Test: scope: a variable is local to its rule or question; the same name elsewhere is another variable

SC3. A statement (one tell, one patch). An id is declared once in it; a statement that adds nothing to a wire is accepted. Its wires are judged together: none of it stays if any of it is refused. Tests: parser: every syntax error is named, with its place, all in one error; nothing is repaired; refusal: deny constraint, and the world is left untouched

SC4. Facts and the matrix. They have separate id spaces: a fact @p and a pattern @p do not clash. Test: matrix and facts have separate id spaces

SC5. A namespace. A fact told with { ns: 'shop' } (or by a world made with new World({ ns })) has the id shop::<id>. A reference without a namespace means one in the same namespace; another is reached only when written out: $other::x, or $::x for the default namespace (facts told without one). One match of a rule, a deny or a question is in one namespace: wires joined by a value are of the same namespace; a wire reached by a written reference may be in another. Two facts merge by identity only inside one namespace. A type declared shared=true, and facts a host provides, belong to every namespace: a bare reference to a wire of a shared type that its own namespace does not have means the one in the default namespace (Test: N5: a bare reference to a wire of a shared type falls back to the default namespace). Questions with { ns } see only that namespace; sync with { ns } works inside it. Matrix wires are in no namespace. The separator :: has no other meaning in the language. Test: scope: facts in different namespaces are never joined by value nor merged by identity; written references and shared types cross

SC5a. Derived wires. What a rule makes is in the namespace of its match. What an aggregate with no anchor (core.aggregate) makes is in the namespace of the wires it counts; when they are in several namespaces, in the default one; when it counts none (a declared empty group), in the world's namespace. Test: N2: aggregate results belong to the namespace of the wires they count; across namespaces, to the default one

SC6. A world. Two worlds share nothing but what was given to both (a library, a host's providers). A fork starts with what its world had and then is its own. Tests: scope: a world given a namespace puts every statement in it; one world never sees another; fork: structural, independent in both directions, and cheap

SC7. A module. A module of the library gets its name as a prefix of its ids, may declare types and slots only under that prefix, and with exports= lets other modules read only the types listed (core.module). A short key that two modules declare along one type's lineage is reported as ambiguous-key. Tests: composition: two different declarations of one key are a conflict unless one says how they combine; modules: ownership of names, exports, and a warning for keys two modules declare
