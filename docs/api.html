API: every public name, with what it takes and returns

import { World, parse, ... } from 'sopworld' (or from the single file docs/sopworld.mjs). This page lists everything the library exports and every public method of a world. Names that start with _ are internal and may change. The language is in language.md, the wire types in reference.md, the behaviour in semantics.md.

Conventions used on this page

  • input is SOP Lang text or an array of parsed wires.
  • A change result is { ok, added, derived, filled, merged, removed, violations }: ids of the facts added, ids of the wires rules derived, values put on existing wires ({ id, key, value, via }), facts merged into others ({ id, into }), ids removed, and the violations (empty when ok). It may also have revised (assumptions that gave way) and issues (soft violations recorded).
  • Errors. Methods do not throw for anything a matrix or a fact can cause: they return ok: false with violations. They throw SopError for text that does not parse, and Error for a call that is wrong in itself (an unknown tier, a host function that would replace a built-in). load is the exception: it throws on refusal.
  • Budget. Every method that computes takes { budget: { steps, ms } } (default 5,000,000 steps, no time limit; the world option budget changes the default). When it runs out, a change is refused with a budget violation and the world is unchanged; a reader returns what its entry says. world.stats() reports the last call.
  • Cost is given in: n facts, r rules, m matches of the bodies concerned, h statements in the log.

The examples on this page use this world:

Making a world

new World(options?)

Options, all optional: ns (the namespace of every statement of this world), facts (below), fns, actions, producers, filters (host functions by name), lemma (the host's lemma function; see register), override (let fns replace built-ins: true or names), library (module name to matrix text, for core.use), maxDepth (12), maxSteps (rule firings per change), budget, decimals, strict (refuse a change that leaves no completion), lookahead (true), solver, searchBudget, rank (reorder suggestions and explanations), vocabulary (names of the question, answer and request wires and their keys).

Properties: wires (Map of facts by id), matrix (Map of matrix wires by id), log (the statements), warnings, version, stamp, actions, producers, options. version is the token to cache by: a fork is born with its world's version, a statement that adds nothing (re-telling what the world holds), a dry run and a refused change leave it, and any change gives a version that no world of the process had before. stamp is internal (it identifies a state within one world, moves with every step of a transaction, and two forks may reuse a number for different states).

Throws if fns would replace a built-in without override. Cost: constant.

Facts the host keeps. facts: { city: (where, world) => [...] } gives the facts of a type from the host's own data (a large static table). A pattern of that type asks the provider with the values it fixes (where, keys to values, strings as their text) and matches what comes back like wires: { id, ...keys } or { id, attrs }, values as values or arrays. They are read in rules, denies, aggregates, queries and ask, are told for tiers, and are never stored, forked, logged or snapshotted. A provider must be pure and stable (the same answer for the same where for the life of the world: what a rule concluded from it is never re-examined), may return more than asked (every pattern value is checked), and should be bounded: each fact it returns costs one step of the budget, so a pattern that fixes nothing pages through the whole table under the budget. A rule needs a wire of the world to fire: a provider's facts alone start nothing. Returned facts are kept by id while the world lives. Cost: a city table of 1,000 rows takes 0.2 ms to build, against 28 ms as wires, and the snapshot is 1 kB instead of 113 kB (node bench/facts.mjs).

World.fromJSON(snapshot, options?)

Rebuilds a world from what toJSON() returned, by replaying its log. Host functions are not in a snapshot: pass the same options. Returns the world. Cost: that of telling the log again, O(h) changes; the open marks of a timeline are forks taken on the way, not replays of their own. A snapshot written with since: base is restored with { base }: the base is forked (its options and functions come with it), checked against the fingerprint in the snapshot, and only the rest is replayed.

World.audit(wires, matrix?, options?)

Checks wires that came from somewhere else against a matrix, without refusing at the first problem. Returns { ok, violations, issues, world }; world holds the wires that could be loaded. Cost: one validation of everything.

World.diff(a, b)

The same as a.diff(b).

Changing a world

world.tell(input, options?)

States wires: facts, matrix wires, or both. Options: dry (evaluate and undo), strict, tier (default told; a tier name for the whole statement, or { key: tier } for some keys, which are then assumptions that assumptions() lists and a told value replaces; a fact marked derived=true with core.source="rule <id>", as a knowledge world ships what its rules derive, has its values at the tier derived, value by value, so a merge with told values of the same identity keeps each value's origin, and why names the rule), ns (the facts go in that namespace: b1 becomes ns::b1, a reference without a namespace points into it), budget. Returns a change result. Cost: O(matches the new wires take part in) for the chase, plus validation of the touched wires; telling matrix wires recompiles the matrix and validates everything, O(n·r).

world.load(input)

tell that throws an Error when the change is refused. For matrices and fixtures, where a refusal is a mistake in the program.

world.use(name)

Loads the module name from the library; the same as telling a core.use wire. The module declares types and slots under its own name (see core.module). Returns a change result.

world.fill(id, key, value, options?)

Gives a value to a key of an existing fact. Options as for tell. A different value for a single-valued key that already has one is a conflict (use revise), except for a fluent, where it is a new statement of the state. Returns a change result.

world.revise(id, key, value, options?) and world.revise(id, values, options?)

Replaces told values, with everything that followed from them, in one transaction. Returns a change result with revised: the cells that were replaced or recomputed.

world.retract(id, options?)

Removes a told fact, the facts that refer to it, and what was derived from them alone. Refused (unknown-wire) for a wire that was not told, and when the world that remains is not valid. Returns a change result with removed. Cost: O(what depended on the wire).

world.replace(id, input, options?)

Retracts the fact id and tells input in one transaction; references to the fact stay valid when the new wire has the same id or identity. Returns a change result.

world.applyPatch(patch, options?)

Applies several changes that must hold together, all or nothing. A patch is an array of { id, key, value } fills, or { wires, fills, sets, retract, replace }: wires to tell, values to add, values to replace, ids to retract, and wires to replace in place. replace: { id, attrs } (or a list of them) gives a told wire exactly the keys in attrs (keys it had and attrs lacks are dropped) and keeps its id, so the wires that refer to it stay; what was derived from the old content is withdrawn. Options: strict, tier, budget. Returns a change result, with replaced (ids) when there were replacements. undo takes a patch back as one statement.

world.sync(collection, input, options?)

Makes a collection of told wires equal to a list, in one transaction. collection is a type (its told facts and those of its subtypes) or { prefix } (the told facts whose id starts with it); input is SOP text or parsed wires. A wire with a new id is told; one whose content differs from what was told is replaced in place (its id, and the wires that refer to it, stay); one that is the same is left alone; a wire of the collection that is not in the list is retracted. Returns the change result with told, replaced, retracted and same (ids). All or nothing. undo takes back what it told and replaced; what it retracted is not given back (use a mark). Options: strict, tier, budget. Cost: one pass over the told wires, then the patch.

With { ns } the list is told in that namespace and the collection is its part.

world.apply(assignment, options?)

Fills the values of an assignment ([{ id, key, value }], as solve returns) in one transaction. Option via names where they came from. Returns a change result.

world.undo(n = 1, options?)

Takes back the last n statements. Returns { ok, undone, removed, added, changed, violations }; nothing-to-undo when the log is empty. Statements that only touched wires of transient types are passed over and kept. A retraction is a statement like the others: undo gives the wire back. Cost: O(h) changes, since the world is rebuilt from the statements that remain.

world.redo(n = 1, options?)

Tells again what the last undo took back (or the last n undos), as the statements they were. Returns { ok, redone, removed, added, changed, violations }; nothing-to-redo when nothing was undone since the last statement that is not transient. If a statement cannot be told again, nothing is, and the world stays as it was. Cost: that of telling the statements again.

world.mark(label?), world.marks() and world.rewind(mark, options?)

mark(label) returns a point to come back to (a fork: the world's next change copies only what it touches); marks() lists the open ones, oldest first, as { label, seq, mark }. rewind(mark) makes the world exactly what it was and returns { ok, removed, added, changed }; the marks made after it are closed. A mark can be used again. rewind(mark, { only }) takes back one unit only: the told wires of a type (only: 'note') or of an id prefix (only: { prefix: 'ui.' }) become what they were at the mark, in one transaction, and everything else stays. What a rewind takes back is kept as after undo(): redo() tells it again, as one step, until the next statement (for only, the unit as it was before the rewind). toJSON({ timeline: true }) also writes the open marks and what redo would tell again, and World.fromJSON restores them, so a host that restarts keeps undo, redo and rewind; with since: base only what came after the base is written (see World.fromJSON).

world.act(request, options?)

Runs an action. request is { action, args }, a core.request wire, or its text. Returns { ok, status, value, result, missing, violations } with status done, missing (arguments to ask for), refused, error (the host function threw), unsupported (no such action) or budget.

The undo contract. One request is one undo step, and so is one sentence (an array of requests, all or nothing). Requests that carry the same options.message tag are one step together, however many calls they took, so a host that runs the clauses of one message one by one undoes them with one undo. Tags must be unique per message.

A host function gets (ctx, args). ctx.tell(input, { now }) queues a statement and returns { ok: true, queued: true }; the queue is propagated and validated together at the first read (ctx.find, ctx.val, ctx.vals, ctx.get, ctx.query, ctx.ask, any use of ctx.world), before ctx.fill, ctx.replace, ctx.retract, and at the end (S57). ctx.flush() does it now and returns the change result; { now: true } checks one tell as it is told. A refusal's violations carry queued: [{ index, ids }], the queued tells involved. Cost: one propagation for the queued tells, against one per tell (node bench/act.mjs).

One sentence, all or nothing. world.act([request, ...]) runs the requests of one sentence in turn inside one transaction: if one is not done (missing, refused, unsupported, error) none is kept, and the result says which (failed, its index), with every result so far (results) and, for a missing argument, what to ask (missing). What they did together is one step for undo and redo, also after toJSON and fromJSON. A retraction inside is undone with the rest. To know beforehand whether each request would be refused, without applying anything, give the readings to score (integration §5b).

Completing a world

world.open(id?)

The open keys (required, no value) of the world or of one wire: [{ id, type, key, ask }]. Cost: O(n), or O(keys of the wire).

world.suggest(id, key, options?)

The values that could go in a key, most plausible first: [{ value, source, count }], source being default, enum, range or wire (a wire of the slot's type). Only values the world accepts are returned; with lookahead, only values that some complete assignment contains. On budget: the array found so far, with a budget property. Cost: one trial per candidate, or one search per candidate with lookahead.

world.next(options?)

What can be done about the open keys without changing anything: { fills, questions, dead }. fills are values that are forced or defaults (kind), questions the keys that need an answer (as question wires with the options), dead the keys with no possible value. With { review: true } also review: the assumptions a host may want confirmed, weakest first; it is a pass over every value, so it is computed only when asked for. Cost: one trial per candidate of each empty slot; nothing at all when the matrix has no required slot and no default.

world.canComplete(id?)

Cheap: whether some empty slot of the world (or of one wire) has a candidate that completion could try: an optional key with a default, or a required key with a default, an enum, a range, or a type that has wires. It does not try the values, so true does not promise that complete() fills anything. For a host that completes after every change and wants to skip the call when there is nothing to look at. Cost: one pass over the wires whose type has such a slot; constant when the matrix has none.

world.complete(options?)

Applies what next found: forced values, with { defaults: true } the defaults, with { choose: true } one full solution of what is left (tier guessed). Returns { filled, questions, dead, pending }. A call on a world that has not changed since a call with the same options that filled nothing returns that answer again at once. The std.acts act complete is different: it applies what std.fill chose for a thing; the solver runs only here.

world.step(input, options?)

One turn of a dialogue: tell(input), then complete(options). Returns the change result with questions, dead and pending added.

world.answer(question, value)

Fills the key a question wire (from next, complete or step) is about. Returns a change result.

world.solve(options?), world.solveReport(options?), world.satisfiable(options?)

Search for values of all open keys that the world accepts together. Nothing changes. Options: solver, budget (the solver's own), limit (the step budget of the call). solveReport returns { status, assignment, reason, stats, solver } with status sat, unsat or unknown (S46); solve returns the assignment or null; satisfiable is false only for unsat. Cost: exponential in the number of open keys in the worst case; the default solver learns from conflicts.

world.solveAsync(options?)

solveReport for a solver that runs outside (solvers.external, dimacs, clingo with an asynchronous exec). Returns a promise of the report.

world.abduce(goal, options?)

What would have to be assumed for goal (wires, as text with ids) to hold: [{ assume, fills, text, cost }], cheapest first; empty when nothing is needed or nothing works. Options: max (10), maxDepth (3 rule steps), maxAssumptions (4). On budget: what was found, with a budget property. adopt(world, explanation) applies one.

Asking

world.ask(query, options?)

Matches patterns (text; ids may be left out) against the facts and returns the bindings, one object per match: [{ variable: value }]. A pattern's own id binds to the matched wire's id. Option at: as of that place in the sequence. On budget: the matches so far, with a budget property. Cost: O(m), using the indexes for fixed values.

With { ns } the patterns see only that namespace, and a reference without a namespace points into it. The same option on query.

world.holds(query, options?)

True when ask would return at least one match.

world.query(question, options?)

Asks for a value, with a status. question is { type, where, absent, seek, mode } or { about, seek }, a core.question wire, or its text. absent (keys) and core.absent= on a question wire match only wires with no value for those keys, as the pattern modifier does. Modes: value (default), list, count, exists, check (is where[seek], or value, the value the world has? yes, or no with actual), abduce. Options: record (tell the question and the answer as wires), suppose (default true: S53), at. Returns { status, value | values, from, via, tier, rests, wires } and, by status, alternatives, missing, reason, issues, howto, supposed, violations. The statuses are defined in semantics.

world.words() and world.interpret(frame, options?)

words() maps each text to its core.word entries, with what each means in the matrix (meanings: { kind: 'action' | 'type' | 'key' | 'value', ... }).

Order. Words keep the order in which they were told: the texts of words(), the entries of one text, the forms of one word, the readings interpret gives for a word with several meanings, the near words at one distance, and the fillers examples uses. So a host declares the most usual word first, and it comes first in examples and in ties (rank keeps the given order). The order survives forks, undo and snapshots; a word retracted and told again goes to the end.

interpret(frame) reads a frame (the host's: its tokens, lemmas, parse) into candidates for score. A frame is { verb, args, numbers, question, mode, ns }; an argument is a word or { word, role }, where role is a word for a key (with, on). A verb that means an action gives { action, args }, one that means a type gives { wires, refer } (a slot that holds a wire gets a described referent), and question: true gives { question }. An argument with no word wire is read as an entity it names by an identifying key, or an enum value spelled as is. Returns { candidates, unresolved, dropped }; each candidate also has reading (which word went where), used, unused and unresolved. Nothing is invented: every value comes from a word or a number of the frame. Options: limit (default 50 candidates), id (of the new wire, default new), near (default true).

A word that is not known (no word wire, no name, no enum value) is read as the nearest known words (a typo): within an edit distance of 1 for words of 4 letters or fewer, 2 for longer, adjacent swaps counting one; only those at the smallest distance; for the verb only words that mean an action, a type or a key. Such a candidate has assumes: [{ word, read }], which score keeps, so rank puts exact readings first and a host can say "(I read X as Y)". A known word is never corrected; near: false turns this off.

Word forms: a core.word may carry several text= forms (text=notebook text=notebooks). A token that is no known form goes through the host's lemma function, if one is registered (lemma: fn or register('lemma', fn)), before near words are tried; no language is built in.

Follow-ups ("no, a red one", "and the price?", "the other one", "tuesday then"): with { previous }, a frame with no verb or no arguments, or one the front end marks anaphor (a pronoun or "one"), correction ("no, X") or other ("the other one"), inherits the previous frame's verb, question flag and words; what it states takes the place of what the previous frame said for the same slot (a correction even in a many slot). previous is a frame, { frame, ids } (the ids the previous reading resolved to: other then describes another wire of the same type, refer.not), or 'told': the last told statement, which the frame then revises (a candidate { revise: { id, values } }, which score judges like the rest). Candidates carry inherited: { verb, words, wire } and replaced (inherited words the reading does not use). A frame with a verb and arguments and no mark is read on its own.

Loose words ("pen two buy", "red house big"): a frame { words, numbers, question } has no verb and no order. Each word that may be a verb (it means an action, a type or a key, or is near one) is tried as the verb with the others as arguments (verbWord), then each action and type that has a word as an implied verb with all the words (implied, kept when it uses one). score and rank order them by what they use; a tie at the top is the host's cue to ask. Bounded by limit and charged to the budget (site interpret; a run-out returns no candidates and budget).

One message may be several frames ("reserve the pen and order ink"). A list of frames is one split of it; a list of lists is alternative splits. Each candidate is then { parts, split }, one reading per frame (new wires new1, new2, ...), and score judges the parts in order, each on the world with the parts before it, as one whole (a frame of a split with no verb, "... and one ink", takes the verb of the frame before it and its words replace that frame's for the same slots): consistent when every part is, with the parts' lacks, assumptions and referents (each marked part) and parts, the score of each. A frame that has no reading stays as an unresolved part (unread: true, with its words in the candidate's unresolved), so a split that leaves a word out loses on words and veto reports words-left-out.

world.examples(templates?, options?)

Example sentences, generated from the tools (actions, types and keys that have words), their slots and the words; the host gives the templates, the library what fills them. templates is { action, statement, question }, each a string with {verb}, {args} and {<key>}, or a function ({ verb, args }) => string; an argument is written role word when its key has a word. Values come only from words and from names the world holds (sample per type, default 2); a number slot takes its min (or 1). Each example is { tool, text, frame, expect }: the frame a front end should give interpret for text, and the reading it should then give, so a lexicon can be tested by reading its own examples back. Options: per (default 3 a tool), all (every slot with fillers, not only the required ones), sample.

world.score(candidates, options?)

Judges candidate readings of one utterance against the world and tells nothing. A candidate is any of { wires, refer } (a statement; refer maps a reference name used in wires to { type, where, ns, not }, a description resolved against the state, not listing ids it is not), { revise: { id, values } } (a change to a told wire), { action, args, of }, or { question } (as for query).

Every scored candidate says whether it was judged and by what (judged, judgedBy): statement, action (a declared action, tried), question, or, for an action the matrix does not declare (the host carries it out), a fallback with what the matrix does know: referents (every $id argument is a wire), slots (the arguments, as keys of of, by default the type named like the action, or as type.key names, told as a wire of that type, fit their slots' kind, enum and range; required keys not given lack, with their ask), denies (no deny fires with that wire). judgedBy is the test that refused, or fallback when all that could run passed (checks lists them); with nothing to check, judged is false. veto does not report action-unavailable for a reading the fallback judged. Returns { candidates, order }; each scored candidate has ok, violations, referents ({ name, ids, unique, fits }: fits are the ids that keep the statement consistent when the description alone is ambiguous), lacks (referents nothing matches, required keys still open, missing arguments, a told subject of a question that is not there; not the value a question asks for, on a subject that is there or on a computed one the matrix has not made yet; a question may be given as an object, a core.question wire or its text), assumes (defaults the statement would rest on), action ({ available, status, missing }), answer, words (for candidates from interpret), and its place: place, why, and for a loser lostTo and on. order is best first by rank (below); option criteria replaces the default ones. See design/formalization.

PatternIndex

new PatternIndex(patterns, { normalize }) indexes a host's sentence patterns by the words they need, so its matcher tries only the patterns a sentence can match. A pattern is { id, kind, needs } plus anything of the host's (handed back as given): needs is a list of word sets, one word of each set must be in the sentence (a literal is a set of one, an alternative a set of several; leave out what is optional and the slots). A pattern that needs no word is tried on every sentence. candidates(tokens, { kind }) returns the patterns every set of which meets the sentence, in the order they were added (so a host's priority order holds); add(pattern) adds one later; stats() says { patterns, words, open, perSentence }. Each pattern is kept under its rarest set, which does not change the answer, only the work. The matching itself stays the host's; words are lowercased unless normalize says otherwise. node bench/patterns.mjs: 3,000 synthetic patterns, 1,000 sentences, 51.5 handed out per sentence instead of 3,000.

schemaCard(world, name?), schemaExamples(world, name?, options?), actReply(world, request, result)

What a host needs to read and to speak about worlds declared with std.schema, generated from the schema, in plain English (hosts translate). schemaCard gives each world (or one) as { world, doc, kinds }, each kind with its words (core.word means= the kind, else its name), acts, attrs (name, kind, values, min, max, step, default, required, refers) and limit; a world that takes any kind of a knowledge type has a kind * with open and from. schemaExamples gives sentences per act and kind with the request each should become ({ world, act, kind, text, request }; per: 2 adds a second for make). actReply gives the reply for an act from its result: what was done (with the old value, from diff), or why not and what is possible (from reason: the attributes the kind has, the kinds that have the attribute, what the kind allows and where the act works, which thing was meant). actReply(world, request, result, { templates }) writes in the host's words: a template per act and kind ('change.seat', then 'change'; for a refusal 'refused.change.seat', 'refused.change', 'refused'), a string with {thing}, {name}, {kind}, {attr}, {value}, {from}, {to}, {why}, or a function of those; with no template for the case, the plain English default. Pass it to turn as reply.

createCatalog(options) and bundleReader(bundle)

Loading knowledge worlds by lookup. createCatalog({ index, vocab, read, cache, lemma }): index.worlds lists each world's schema, depends and shards ({ id, path }), as in sop-knowledge-worlds' index.json; vocab maps a word to shard ids (vocab.json); read(path) is the host's (a file, fetch, a bundle; a promise or a text); cache is any { get, set } (a Map by default); lemma(word) gives other forms to look up (none by default). shardsOf(word) lists the shards (nothing read); plan(shards) the paths to tell, schemas of the worlds and of what they depend on first; fetch(word) reads them; into(world, word) tells them (schemas once per world) and resolves to { shards, told, ok, violations }; intoSync does the same when read answers at once. A failed read is not remembered. bundleReader({ files }) reads a bundle written by node tools/build-bundle.mjs <catalog dir> <out.json> <word|shard|world> ....

bundleThenRead(bundle, read), listOf(world, type, slot?, value?), loadBundles(world, bundles)

Knowledge readers every host needs. bundleThenRead is a read(path) for a catalog that answers from a bundled subset at once and asks read for the rest, so the first paint needs no network; .reachable() says whether the catalog answered the last time. listOf gives the names (or ids) of the loaded wires of a type, optionally those whose slot has value. loadBundles tells bundles[name] once into a world for each std.schema.world ... bundle=<name> (a world-level bundle) and returns the names told. A catalog also looks a word up once, and finds a form its vocabulary lacks through a loaded core.word (ants means ant) when given the world (into, intoSync).

createCatalogs(list, options?)

Several knowledge repositories at once, in an order of precedence: list is [{ name, index, vocab, read, cache? }] (each as createCatalog; options.lemma is shared), and the first catalog wins. shardsOf(word) gives "<name>:<shard>" from every catalog that has the word. into(world, word) tells them catalog by catalog (intoSync when every read answers at once). Each wire keeps its catalog in its source (core.source="<name>: <source>"). A wire that another catalog already told, under the same id or as a fact of the same type about the same name, is told only if it has the same values. If not, it is reported in conflicts ({ id, kept, dropped, path, keys }) and the first catalog's version stays. std.know.fill and typed needs then read what was kept.

turn(world, readings, options?) and TURN_STAGES

One request, end to end. readings are the candidate readings of one message, best first: each a request { action, args }, a list of requests (one sentence), or { requests }. Each is tried on a fork (nothing changes); the first the world takes is applied as one sentence (all or nothing, one undo step) and the result has status: 'done', reading (its index), results, diff, why (the chain of each changed value), guesses (values filled by tiers, with their source) and replies (from actReply, or options.reply). Otherwise a graded fallback: ask (a reading only lacks an argument: question, missing), elsewhere (the kind is known but the act or the attribute is not here: the reply says what it can do and where), unknown (the best guess named in a question). Every result but nothing has replies (for ask and unknown, the question), and lists the readings dropped with the reason.

turn is turnFlow with TURN_STAGES (read the readings given, dry run, apply, reply; the fallback when every reading is refused): the library has one request pipeline. A world that declares its own std.turn stages runs them.

schemaGrid(world, name?, options?) and gridTests(cases, options?)

The coverage grid: for every world × kind × act the schemas allow, the example request (schemaExamples) run on a copy of the world that holds one thing of each kind, with what came of it in expect: done, with the kinds added, the number removed and the keys changed; or not, with the reason (the holes are the cases not done). gridTests(cases, { importFrom, make }) writes a node:test file that runs each case again on make() (a function the host exports from importFrom) and checks it.

ledgerAppend, ledgerGroups, ledgerKey, stageOf, STAGES

A failure ledger: a failing case is data. A row is { text, world, language, happened, expected, stage, class, source, first_seen, build, was_passing }; ledgerKey is its source, text and world. ledgerAppend(rows, add) gives the rows of add that are new (old rows are never rewritten or added again). ledgerGroups(rows, { signals, examples }) groups by stage (one of STAGES: reading, routing, filling, acting, replying), class and the first of the host's cause signals ([name, row => boolean]) that holds, largest first, with examples spread over sources. stageOf(turnResult) files a failed turn. parseText(world, text, options?), grammarOf(world, options?), nounPhrase(node, cats?)

The language-free part of reading: a grammar (a knowledge world about a language) holds the language as facts — g.word text= lemma= cat= (more keys are features), g.rule lhs= rhs= ... (in order; X? optional, X* any number, X+ one or more), g.coord word= — and parseText reads text with them: every complete parse of start (default S), best first (fewer nodes, then the higher coordination), at most max (8). A node is { cat, span: [i, j], rule?, word?, lemma?, feat?, children?, coord? }; rule is the id of the rule that built it.

If an alternation actually rewrites the message, its current API supplies no edit alignment: source.status is unavailable, tokenRanges is null, and nodes have no sourceRanges. A feature may declare from_id=true to carry the exact selected provider wire ID. This is mutually exclusive with from_key and value; false or any other flag value is rejected. It works uniformly for ordinary providers and core.word, respects source filters and source_id, and preserves distinct identities when providers share the same text. The value is the actual wire identity, not a display name, binding ID or synthesized semantic label. Source-family mappings can therefore use one binding for a declared family while retaining the exact lexical sense used by each candidate.

Compiles a loaded SOP declaration module into explicit grammar options and semantic composition templates. The caller supplies all eight type identities in types: binding, feature, filter, rule, map, node, step, agreement. projectTemplates(jobs, options?)

Projects an already composed semantic JSON context without requiring a parse tree. Each job is exactly {template, context}: template names a declaration in options.templates, and context is ordinary finite JSON. Jobs are alternatives, not instructions to merge their results. Output is {candidates, failures} with {index, value} candidates and {index?, reason} failures. Indices refer to the original job positions; successful alternatives remain separate and ordered.

The template language is exactly the one used by composeParses: ordinary JSON builds objects/arrays, {$get: ['path', 0, 'key']} copies an own-property path from the supplied context, and {$literal: value} quotes data containing directive keys. There are no additional operators, callbacks, conversions or implicit bindings. Optional guards: {templateName: [{left, right}]} compares projected operands using structural JSON equality before producing a candidate. Object key order is irrelevant; array order and primitive types matter. A missing path yields missing-binding; unequal operands yield guard-rejected. These are different failures, not a substituted null or default value. Null is a valid context: a constant template can project it, but a path lookup against it fails.

All template and guard declarations are checked before any job can succeed, including unused declarations. Unknown guard keys and malformed templates yield an unindexed failure with no candidates. Each context is fully validated/copied before its guards run: sparse arrays, accessors, symbols, hidden properties, non-plain objects, nonfinite numbers and cyclic/deep data are refused, including unsafe fields that a template would not read. No accessor is executed. Outputs are detached from input contexts and other candidates.

budget defaults to 20000 and maxDepth to 64 (maximum 256). One evaluator budget covers declaration checks, job enumeration, context copying, guards and projection for the entire batch. Exhaustion adds truncated: true; earlier candidates may remain, but are not evidence that all alternatives were considered. A depth failure is explicit and indexed when caused by one context. Applications must account for all failures and upstream enumeration limits before acting on a candidate. The existing composeParses traversal and its budget accounting remain unchanged; projection's additional full-context/declaration checks are deliberately charged.

Role arrays can preserve a selected object's entire selector alongside a separate result, or retain a marker and argument sharing the same semantic role. The projector does not select frames, validate licences, infer role semantics or build request graphs by itself. Such declarations remain the adapter's responsibility.

composeParses(parses, options?)

composeParses(parses, { rules, lexical, guards, budget, maxDepth }) evaluates declarative semantic templates over each parse independently. rules maps exact production IDs; lexical maps lexical categories. Ordinary JSON objects/arrays assemble a record. {$get: path} copies an own-property path from {node, children}, where children contains already composed child values. {$literal: value} quotes JSON containing reserved keys. Every child must have a mapping; an explicit {$literal: null} can acknowledge syntax-only material.

guards maps production IDs to arrays of {left, right} template pairs. Each pair is evaluated in the same {node, children} context after the children compose and before the parent's output template is evaluated. Both operands must exist and be structurally equal JSON. Object key insertion order does not matter; arrays are ordered, primitive types do not coerce, and JSON numeric zero has one value (-0 and 0 agree). No approximate numeric or domain-specific equality is inferred. Several pairs are conjunctive; an empty array imposes no condition.

All guard declarations are validated before any candidate is produced, including those for productions absent from this batch. Guard keys must name a declared rules entry; malformed maps/pairs/templates cannot silently disable a check. A valid unused guard's binding paths are resolved only when its production occurs. Unequal operands report guard-rejected; missing paths report missing-binding; malformed pairs or unknown production IDs report invalid-guard. Other existing JSON/path errors remain explicit. Declaration validation, operand evaluation and structural comparison share the composition budget. A declaration error has no parse index; later exhaustion may retain candidates already completed.

The result contains candidates: [{index, value}] and failures: [{index, reason}]. Templates and copied values must be plain JSON: special object prototypes, sparse arrays, extra array properties, symbols, accessors and non-enumerable object properties are rejected. Accessors are never executed by binding/copy evaluation. The input is a parseText result; arbitrary malformed outer parse containers are not an alternate input format. Missing mappings/features reject that parse. Alternatives are retained without merging or ranking. Unmapped coordination is rejected. budget defaults to 20000 traversal/copy steps; maxDepth defaults to 64 (allowed range 1–256). Exhaustion retains earlier candidates and marks truncated: true; parser truncation also propagates. A candidate is a declared interpretation, not proof of completeness, exhaustive parsing, vocabulary validity or successful instance resolution.

resolve(world, phrase, options?)

The things a noun phrase names (std.schema.thing wires), and how sure the reading is. phrase is text, read with options.grammar (parseText's options, start NP) and options.cats (nounPhrase's), or a nounPhrase result. The kind is the head's lemma or a word that means it (core.word text= means=), else a kind one swap or letter away (a slip). Modifiers and a name are values of any key, and a core.word ... of=<key> word counts for that key only. A PP narrows to things with a key that refers to the one thing its noun phrase names. quant (all, each, both) and a phrase with no noun give the set. An ordinal, or a number after the noun, picks one (the id <kind><n> first); a number before the noun must be the count. A coordination is the union of its parts. A pronoun is the newest thing in focus (options.focus, ids newest first, else the std.focus.last wires that name things).

Also: a coordination whose word the grammar marks kind=choice (x.coord word=or kind=choice) is asked, never both and never the last ({ ids: [], ask: true, which }). A part without its noun borrows one: a bare number takes the noun of the part before ("tables 1 and 2"), any other part the noun of the next part ("the red or the blue house"). A coordination inside a phrase is distributed ("red and blue cups"). A part of a set (a number, quantifier or determiner with a PP and no noun: "two of the tables") is the whole set when the count covers it, else asked. A modifier that core.word maps to std.other ("the other one") keeps the things of the kind that are not in focus. A pronoun also carries guess: { word, ids }, for the host's "I took it to mean ..." sentence.

More of what it reads:

  • A result that is not one reading carries failure: unknown-word, unread, unknown-kind, none (nothing fits), no-number, no-focus or ambiguous (also ask: true).
  • A negation lead (the grammar's cats.neg, as in "not the blue table") keeps the things of the kind the modifiers do not pick.
  • A relative clause after the noun ("the table that is red": a rule NP -> NP RELPRON COP MOD) folds into the modifiers.
  • A bare name (NP -> NAME) is the one thing of that name.
  • focusFor: 'pronoun' keeps the focus for pronouns only.
  • Coordinating words are read from word= or text=.

Returns { ids, tier, how }: tier is user (the words picked), scene (the only one of its kind), focus (the focus chose among several) or slip (the least sure in a coordination wins); how lists the steps, so a reply can say what it assumed. When it cannot resolve, it returns { ids: [], why, which?, kind?, unknown? }.

Morphology for language worlds (std.morph). The primitives are the same for every language and run in both directions; nothing here knows a language.

A language world declares (type names can be changed with morphOf(world, { types })):

  • paradigm classes: m.class name= parent=? drop=? alt=<from>><to>. A class inherits its parent's cells and overrides some; drop is what the lemma loses to give the stem; alt is a stem alternation, from>to, optionally anchored with @vowel (the stem's last vowel, from m.vowel text=) or @end. The functions:

  • morphOf(world) compiles these once, with a suffix index.
  • generate(m, lemma, class, features) gives a form.
  • analyse(m, form, { dictionary }) gives [{ lemma, class, features, form, exact }]. It looks up the suffix index and checks each candidate by generating it again, so no form list is stored. planner(store, options?), factStore(worlds), PlanLive, readMethods, PLAN_LIMITS

std.plan: goals reached by methods that are knowledge (k.procedures, in the format of the knowledge repository's Q44), decomposed into acts over a live world. factStore(worlds) reads published worlds ([{ id, schemaText, shards: [{ text }] }]) into facts merged by identity, read lazily per type. planner(store, { chain, prefix, roles }) reads the methods (readMethods). chain is [{ type, keys }], what "is a kind of" is, or the store's std.know.chain of= key= facts. plan(goal, live, { fixed }) takes a goal { act, roles } and a PlanLive (a working copy of the live world: things, history, the world schema's kinds); fixed ({ binding: value | [values] }) gives choice points the host decided (still checked: one that breaks a match is refused), and seed: null gives the first solution, the same every time. The plan returns:

  • method, methods (every method used, in order);
  • lines (one per act), explain (one short line per step: the method, what the step is for, the act);
  • requests (role-named requests for std.acts), skipped, effects;
  • or asks (a needed role missing), or refused with tried (each alternative and why it failed); truncated past PLAN_LIMITS.

  • The choice points of a method are solved jointly before its steps, with solveChoices: one slot per value, the slots of a binding made in order and different, every hard match checked as soon as what it reads is chosen.
  • Matches may read one key several times (n= tells them apart): - differs= names a binding whose values must not be shared, or the binding itself for values different among its own; - soft=true only doubles the weight of a candidate that holds it; - a binding's matches hold on every source, together included.
  • about= gives the statements of the catalog about a binding's things, for the types in planner's about option.
  • seed sets the draw, and chooseLimit bounds the search (default 200,000 nodes).
  • The plan says what was chosen in chosen, or refuses when no choice satisfies the matches.

learnRules(world, cases, options?)

Induction from cases (abstraction round, item 4). Cases [{ text, frame }] that share a frame (ask of a key) and a length are anti-unified by the library's own induce into one reading rule:

  • the words that differ become variables;
  • a variable that fills the frame is lifted to the kind of the thing it names, by a pattern on that thing's fact.

relatedCases(world, case, options?), ancestorsOf(world, id, options?), kindChain(world, id) and judgeOnRelated(answer, case, related)

A case is never single (abstraction round, item 0). Its related cases are perturbations of it along named axes, as in metamorphic testing (docs/generalisation.md has the picture and the literature). relatedCases goes up from a case { frame, text? } (a frame of readByTypes) along an axis, then down to other members. The axes:

  • filler: up the chain of kinds (kind, class, is, is_a, then the type), and down to the other things below. The distance is how far up the case and the other thing must go to meet: 1 = the same kind, 2 = kinds that share a parent, and so on.
  • key: the other keys of the same holder.
  • wording: the same frame in other forms. Each form operator is run backwards and tagged form:<name>: - the language world's alternations (alternations, from alternationsOf); - noise or learnt operators (operators, for example from learnFormOperators); - a word for its synonym through word senses (form:synonym). - the paraphrases the language world declares (w.lang.en.variant frame= alternation= canonical=), tagged variant:<alternation>, for a case with langFrame (the frame it was said in) and roles; each is realised with realiseFrame.

With these, the tester can say "fails under operator X".

A related case is valid when it is legal in the world (it has an answer), when its wording, made by substituting the filler, reads back to the same frame, and when it is not a known case. Each one is tagged with its distance and the axes changed.

The graph is layered: a thing has several parents on several axes. edges ({ key: axis }, by default kind / class / is / is_a as kind) names them, and ancestorsOf(world, id, { depth, edges }) walks them breadth first. Related cases are deduplicated by frame and stratified per distance and axis (n each). The generalisation test tools/generalisation-test.mjs takes one example and a host and gives a table per distance × axis, naming the pattern of breaks. With split and oracle it judges every clause of a compound text: the host's answer to the whole text must hold the world's answer to each clause, so answering one half fails. The skill skills/expand-and-test-case hands the failures to learnRules. judgeOnRelated(answer, case, related) judges a fix both ways: on the case alone and on its valid related cases by distance (byDistance). Judged that way, a fix that passes only its case shows a share of 0.

It returns { candidates, best, unread, repaired, mood, complete, why? }:

  • unread are the words the best reading did not use; a reading with words left is not complete, and those words are never arguments;
  • repaired are respellings (a reader's via: 'spelling'), each confident or not (confidentTypo: the typed word and its respelling are whole words of 4 letters or more, within the spelling budget of 1 edit, 2 from 8 letters, with the first letter kept or the first two swapped). A reading whose repairs are all confident is complete and lists them in named, so the reply can say them; any other repair makes it incomplete;
  • mood is read before the act by moodOf: question (a final ?, a question word or an auxiliary first), wish (a wish of the language world first, <lang>.fn view=wish: "I want a red circle", a request), statement (a first-person subject first, or a name and an auxiliary: "I have two kids", "Tom has 5 apples", unless the name is a thing of the world), fragment (nothing, articles and letters, or the speaker alone: "my", "an a"), else imperative (also after a polite lead: "could you add a table"). Hesitations, lead fillers and politeness of the language world are passed over. detail: true gives { mood, by }. An act frame needs an imperative, a wish or a question.

The mood words come from the language world (<lang>.wh, <lang>.aux, <lang>.pron person=1, <lang>.det, <lang>.fn), with English defaults for a world that has none.

readByTypes(world, text, options?), typedLexicon(world) and nearWords(world, word, options?)

Type-driven reading (abstraction round, item 1). Each content word is typed through the world itself:

  • a thing: a fact's name;
  • a kind: a type, or a kind, class or is value;
  • an attribute: a key that facts carry, or a relation the knowledge declares (k.kinds.relation type= key=). A question about a declared relation with no value yet is understood, and its frame says known: false with an empty answer;
  • a value: a key's value;
  • an act: a word of an action;
  • a known word: a core.word. A verb that means a key asks for that key.

The candidate frames are the relations, inverse relations and acts whose argument types the words fill, each word used once:

  • ask: the key of a thing or kind, with its answer;
  • find: the holders of a kind with key=value;
  • act: an act with typed arguments: the kind to make (a type), the thing to act on (a name), and values of a closed set by their key (make a blue shape → { kind: 'shape', colour: 'blue' }).

Word order and function words only rank the frames, so paraphrases in any order read to one frame. Options: question (words that make a question), skip (words passed over), lemma. The result also says whether the reading is complete (reviewer 03:20). left lists the content words the best frame does not consume, and complete is true only when nothing is unread or left: an incomplete reading is not final. Words the world does not know are listed in unread. typedLexicon is the lexicon, memoised per world. The language's own facts (k.words, w.lang, k.genres, k.interest) are not content.

Lexical generalisation (item 3): nearWords(world, word, { senses }) gives a word's near words through word senses (k.words.sense: word, synonym, is_a, kind_of):

  • a synonym costs 1, both ways;
  • the nearest kind (is_a) costs 2;
  • further kinds cost 3 or more.

By default the senses are the world's own; a host passes senses(word) from a lazy catalog. readByTypes reads an unknown word as its nearest known word when the cost is within near (default 3). The result lists each such reading in near ({ word, as, cost, via }), and the cost lowers the frame's score.

inflectBy(world, word, op?, options?) and articleFor(world, word, options?)

Plurals and articles from a language world's facts (std.morph). inflectBy changes a word by ordered suffix rules (op= order= suffix= after=consonant|vowel unless_suffix= min_length= replace= | add= drop=), with irregular forms first. The pairs singular= plural= read_only= serve the plural and singular ops only, each in its own direction. The forms lemma= form= vform=|degree=|num= serve the op's cell (past, ing, comparative and so on); one marked read_only=yes or variant=yes is never written. Two pairs of one word in two registers (register=classical|common: cacti, cactuses) are written as the common one unless register is asked; all: true gives every form, for a reader. Rules in sets (set=act|lemma) are read in the lemma set unless set is asked; a rule with exception= applies to the words of that list (<lang>.noun.exception kind=<name>-suffix|<name>-word), unless_is_singular=yes spares a word in -is unless it is an is-plural, and the singular of a listed pair is itself (bus, iris). A rule with keys it does not know is not applied. articleFor gives the determiner whose before= is the sound the word begins with, by the longest onset (begins= sound=) that matches, else by its first letter. The types default to w.lang.en's (w.lang.en.inflect, .irregular, .irregular_form, .det, .onset). discourseRealiser uses both when the language world has them: {kind:num=pl} gives the plural, and "a" or "an" takes its form from the next word.

discourseRealiser(world, options?) and discourseTemplates(world, type?)

Sentences for composition frames from a language world's discourse templates (w.lang.en.discourse: a move, a register, a text with {slots}). The realiser picks, by seed, a template of the frame's move and register whose slots it can all fill. It fills them from the frame, the fact it cites, the story plan and the outline.

  • A story sentence tells its own element, and only elements told before it.
  • A move about the topic says the first claim.
  • No sentence is used twice while another fits.
  • What has no fitting template stays without text; compose lists it in short.

How a fact becomes a clause and a name a noun phrase is the language's, so the host gives clause(fact), np(name) and inflect(word, features). The defaults only join words ("the penguin eats fish"). A host's own fill(slot, frame, context) is tried first. compose uses this realiser when the world holds the templates and no realise is given. Each frame then records its template, which writeDocument keeps.

writeDocument(world, composition, options?) and readDocument(world, id)

writeDocument writes a composition by a genre as a w.document live world. The world must use the knowledge repository's w.document schema. Each part becomes a slide, when the genre's unit is slide, or a chapter with a paragraph. Each frame becomes a sentence with its move and fact (the ids of the wires it states). readStory(world), storyPlan(kb, options?) and STORY_RELATIONS

Story plans from the knowledge repository's k.story. Each element (setting, protagonist, goal, target, obstacle, attempts, helper, means, turning point, resolution, ending) is a choice point. Its domain is the names of the facts of the types it is filled from (fills). The constraints (element relation other) are read as facts: hard ones prune, soft ones weight the draw (soft, default 30). solveChoices solves them jointly.

  • Elements the constraints link to what is already decided are decided first; the host's fixed choices come before everything.
  • An element that occurs several times (attempt, 0 to 3) is made in order, each different.
  • STORY_RELATIONS says what each relation means over the catalog's facts. It is the one table that knows their shapes; a host adds to it or replaces it with relations.

readStory(world) gathers what a plan reads from a world holding k.story and the catalog worlds it names.

The result is { plan: { element: value or [values] }, soft: [names held], nodes }, or { why, at }. With a story genre, compose tells each story move from a plan: the elements of that part and move, one sentence each. The topic is the protagonist when it can be; otherwise another hero is chosen and short says so. The plan is in story.

solveChoices(vars, { domain, ok, weight, seed, limit })

Choice points solved jointly (std.plan). Variables are decided in order. domain(v, partial) gives the candidates of a variable, given the choices made before it. ok(partial) checks the hard constraints, and false prunes the branch. weight orders the candidates by a seeded weighted draw, so the first solution found is a weighted sample (with seed: null, by weight, ties in the given order); weight 0 is never drawn. The search is bounded by limit nodes. The result is { values, nodes }, or { why, nodes, deepest } with the variable that could not be filled.

measuresOf(world, fact, state?), shapeShare(feature, x) and interestModel(world)

The parts of interestOf. measuresOf gives the measures the library computes from facts and the text being written (state: topic, said, moves, move, since, session, measures). shapeShare is the share of a feature's shape (rising, falling, peak, step) at a value. interestModel reads the world's k.interest.appraisal and k.interest.feature facts, or gives null.

arbitrate(world, request, options?)

The arbitration contract: one verdict per declared world for one request. own: the world has the kind (or the thing, or a view whose state has the attribute), allows the act, and its dry run takes it. decline: it has no use for the kind, so it declines the verb; this rule is the library's, not the host's. refuse: it has the kind, but the act is not allowed or the dry run refuses. signatureOf(world, token, options?), chunk(world, text, options?), minePatterns(world, sentences, options?) and patternReader(world, cases, options?)

Type signatures and a finite pattern inventory (reviewer 02:15, owner 18:10). signatureOf gives a word's signature as three levels, [fine, middle, coarse]:

  • knowledge types first: a thing <its type> / <thing> / <N>; an attribute <attr:key> / <attr>; a kind; an act; a verb the world declares for a key <verb:key> / <verb> / <V>;
  • a number <num>;

  • other words by their ending (<w-ing>, <w-s>, …).

resolveEllipsis(world, text, previous, options?)

Ellipsis (fragment) resolution (reviewer 03:20): a verbless continuation such as "it to the top right" or "and still up" reuses the previous act { act, args } with the roles the message gives, read by type. A thing is read by its name, and a pronoun in pronouns keeps the previous thing. A value of a closed set is read by its key; multiword values like "top right" count. The result is { act, args, reused: true, changed }, or null when the message names an act or gives no role.

Relative continuations, as in real turns ("more to the left", "a bit lower", "not the first one, the middle one"): a direction of the language world (<lang>.lex name=acts.dir item=...) goes in args[dirKey] (dir); a word of more marks the move as relative (relative: { more: true }, and small: true for a word of small), and "even more" alone repeats the previous direction. A position picks among the things of the previous thing's type, ordered by x: an ordinal (<lang>.ordinal text= value=) or a word of positions (first, last, middle). Of clauses split by commas, one with a negation (<lang>.neg text=) is the one rejected. lang (w.lang.en) and fold read another language with its own words.

readEnsemble(world, text, options?), defaultReaders(read?, canonical?), riskCoverage(rows) and calibrate(rows, options?)

Several readers, one confidence (reviewer 02:30). Readers run as parallel voices, not a fallback chain. Each is (world, text) -> [{ frame, unread?, cost?, specificity? }]. The library's own are types (readByTypes) and canonical (readCanonical, the language world's normalisation before the typed reader). A run of one reader with other options is not a second vote; a host adds independent readers (readFrames, parseText, patternReader) as its own voices. The candidate frames are pooled with features:

  • agreement: the readers that proposed the frame, weighted by weights (default 1 each; learnt from cases, for example each reader's precision on a training half);
  • words left unread;
  • the cost of assumptions;
  • specificity.

std.decide (kind ensemble) combines them. The result is { frame, confidence, voices, candidates, ranked, ask? }, where confidence is the weighted share of the readers that proposed the winner. Coverage comes first: a reading that leaves content words unconsumed loses to one that consumes them all, and complete says whether the winner does. Below threshold, when the winner is incomplete, or when two readings tie, ask holds the competing frames, for a question back instead of a guess.

riskCoverage(rows) turns [{ confidence, correct }] into the risk–coverage curve: for each threshold, the share answered and the share of those that are wrong. tools/bench-ensemble.mjs measures the readers alone and together on PSys2's form pairs.

calibrate(rows, { method }) maps a reader's confidence to a probability of being right, from held-out rows [{ confidence, correct }]: isotonic (the default: pool-adjacent-violators, a non-decreasing step function, interpolated between steps) or platt (a logistic curve fit on the log loss with Platt's smoothed targets). It returns { method, p(score), steps | params, brier: { before, after } }, so a confidence threshold can be set as a probability.

joinList(items, options?), clauseOf(world, fact, options?), actSentence(world, act, roles, options?) and renderFrames(frames, options?)

choose(world, kind, candidates, options?), rankingOf(world) and learnRanking(world, kind, cases, options?)

One way to choose (reviewer 01:00). parse(text, options?), tokenize(text, options?)

parse returns the wires of a text: [{ id, type, attrs, pattern }], attrs mapping each key to the array of its value tokens. Options: anonymous (a declaration may leave out its @id, for queries), lenient (read what versions before 0.6.1 read: an id twice in one text, escapes JSON does not have, a quote or backslash in an atom). It throws SopError listing every error of the text (the list). tokenize returns the tokens: [{ t, line, column, offset }]. Cost: linear in the text.

format(wire, options?) and serialize(wires, options?)

format writes one wire: on one line; with { multiline: true } one entry per line; with { canonical: true } in the canonical form (entries sorted by key, strings in one spelling). serialize writes several wires, each followed by a line end, with the same options; serialize(wires, { canonical: true }) gives the same bytes for the same wires.

str(value), valueText(value), quote(text), readValue(token), writeValue(value)

str gives the text of a string token (escapes decoded) and returns any other value unchanged; valueText is the same as text, with '' for no value, and is how every module of the library reads a value's text; quote gives the string token of a text, in the canonical spelling (the escapes of JSON). readValue gives a token as data, { kind, v } with kind atom, string, ref or var; writeValue is its inverse (and throws for another kind). They are what a host with its own parser needs to hand over wires.

SopError

What parse, tell and the other methods throw for text that is not SOP Lang. It has message, line, column and offset of the first error, and errors: every error of the text as { message, offset, line, column }.

unify(a, b, bindings?) and walk(term, bindings)

unify matches two values (an atom, a ?variable, a $reference, also $?variable) and returns the bindings, extended from those given, or null when they cannot be the same. walk returns what a value stands for under bindings.

abduce(world, goal, options?) and adopt(world, explanation)

abduce is world.abduce. adopt tells an explanation's wires and fills (tier guessed) and returns { ok, results }.

induce(examples, options?), induceRule(examples, options?), induceSlots(wires, options?)

induce generalises examples ([{ when, then }], text or wires) into one rule, or with { kind: 'deny' } into a deny: { text, calcs, tests, skipped, coversNegative, variables, examples }. Options: name, why, tolerant (skip examples of another shape), negatives, budget. induceRule returns only the text. induceSlots proposes slots for observed wires. What they return is text to review and tell.

quantity(value)

Reads a number with an optional unit: { n, unit }, or null.

solvers, Problem, Sat, toDimacs(data), toASP(data)

solvers.cdcl() (the default) and solvers.backtrack() are built in. solvers.external({ run }), solvers.dimacs({ exec }) and solvers.clingo({ exec }) hand the problem to a program outside; what it proposes is verified by the world. new Problem(world) is the search problem of a world (variables, nogoods, verify, toJSON); toDimacs and toASP write it for a SAT or an ASP solver. Sat is the built-in SAT solver (addClause, solve, model).

builtins, aggregates, GRAMMAR, MODIFIERS, SCHEMA_TYPES

Tables, for tools: the built-in functions and aggregates by name; for each matrix wire type the attributes it reads (GRAMMAR; a name that ends in . is a prefix); the attributes that may stand on any pattern or template (MODIFIERS); the types that make a wire a matrix wire (SCHEMA_TYPES).

version and build

version is the version of the library. build is { version, hash, date }: which build a single file is (hash and date are null when running from the sources); docs/version.md says the same.

calibrateReference(world, id, options?)

Capture a valid std.reference.set and calculate its positive median normalization. options.family supports an aliased reference module; options.budget bounds world validation, capture and sorting. Returns {ok, snapshot, issues}; failure has no snapshot. The source world is checked first, so unrelated invalid state also prevents capture.

The detached, deeply frozen snapshot has format sop.reference.calibration, schemaVersion 1, method median, value/unit, historical reference identity/version/property, sample identities/numeric values/original tokens/units, and the complete factual provenance closure reachable from supplied sample provenance. Distinct equal samples count separately; repeated references to the same sample do not. Every reference in copied evidence resolves inside that copied closure. Missing optional provenance remains missing, not invented. A finite positive result is required for normalization.

The snapshot can be serialized as JSON and retained after source changes. Freezing protects the returned object only: JSON parsing does not preserve that protection, and neither freezing nor a recorded version authenticates observations or prevents a host replacing a persisted revision. No publication registry, verified restore API, axis binding, unit conversion or std.calibration wire schema is supplied by this function.

world.retainRevision(owner, revision, definition, options?) and world.retainedRevision(owner, revision)

Retain a definition under two nonempty string keys. The first successful publication fixes its canonical JSON contents. Identical reuse returns created:false; a different definition returns a retained-revision violation. Reads return the deeply frozen {owner, revision, definition} record, or null. Publication returns {ok, created, retained?, violations}. dry:true validates without retention; budget bounds copying, canonicalization and comparisons. Definitions inserted inside a refused transaction roll back. A validation function cannot publish definitions as a hidden side effect.

Definitions accept finite JSON primitives, dense arrays and plain objects, to 64 nested container levels. Object key order is irrelevant, array order matters, and negative zero normalizes to JSON zero. Accessors, cycles, sparse arrays, hidden/symbol properties, nonfinite numbers and non-JSON objects are refused. Unicode strings are preserved without normalization. Inputs are detached; returned nested objects/arrays are frozen.

Retained definitions are outside the ordinary fact log: undo, redo, partial/full rewind and replay-based retraction cannot erase them. Forks share immutable entries but isolate subsequent insertions; state adoption merges registries and refuses conflicting reuse before changing facts. A successful partial rewind also preserves publications made by its commit listeners. Retention itself is not an undoable domain operation and does not append a fact-history step.

toJSON() includes retained definitions when present, also for delta and timeline snapshots. World.fromJSON() restores and checks them before fact replay; conflicts with a delta base or within retained entries are refused. Older snapshots without the registry still load, but cannot prove an omitted publication history. JSON persistence is not authenticity: an attacker or external editor can replace the only copy of a definition, and independent forks have no global publication authority until reconciled. No space/point interpretation, axis migration or automatic calibration binding is supplied by retention alone.

retainPointSpace(world, id, options?)

Captures a numerical w.legend.space and publishes its immutable definition through world.retainRevision. family selects an aliased legend module; budget bounds validation, capture and retention; dry:true checks publication without inserting it. The result is {ok, created, retained?, violations}. An invalid world, graph space, empty axes, missing root frame or empty space/frame revision is refused.

Each axis records id/name/order/kind/canonical unit ID, supplied numeric bounds/weight/normalisation/period/step, optional scale, and all its declared units as {id,name,factor,offset} sorted by qualified ID. Missing optional fields stay absent. Numeric spellings normalize to numbers; source declaration order does not affect publication. Subtype-specific extra metadata is not a coordinate contract and is not captured.

assessPropertyChange(world, options)

Added with 0.191. Assesses one exact native property using published trace records and retains its evidence. Load std.trace and std.reply first. Required options: request, step, before, after, expectation (trace record IDs); source, sourceType, key (native property identity); and nonempty owner, revision strings (retained assessment identity). family selects an aliased trace module; replyFamily selects an aliased reply module. The reply schema and its registered evaluator must be loaded. budget bounds checking/capture/retention; dry:true leaves no retained entry.

Before/after are observations of the same step/invocation, with the named phases; the step belongs to the request. Each observation must identify exactly one input for the selected source/type/key. Expectation and before-input must occur in the step's input list; after-input must occur in its result list. Expectation is a typed trace input containing the resolved native key and desired canonical SOP tokens. The resolver, not this evaluator, establishes its relation to semantic intent and preserves mapping provenance.

Comparison is exact, ordered token-array equality: repeated values and quoted/bare categories remain distinct, and 1 differs from 1.0. It does not infer numeric, perceptual, ontology or unit equivalence. unchanged means both before and after already equal expectation, without claiming operation success. changed requires after matching, before differing, a confirmed step and different before/after source versions. A valid but unmatched result, unconfirmed step or changed values without a new source version produces unconfirmed with a specific reason. Invalid/ambiguous correlation refuses publication.

Returns {ok, created, retained?, assessment?, claim?, violations}. The deeply frozen assessment has fixed format sop.reply.exact-property, schemaVersion 1, normalized request/step/subject/expectation and observation snapshots, plus derived status/reason. Reusing owner/revision for different evidence fails. claim is an id-less wire {type, attrs} for the selected reply family; give it an ID when telling it. std.reply.property is closed and requires owner/revision/status; its validator recomputes the result from retained contents, including operation inputs/results and repeated-record identity consistency. Changing live trace records cannot rewrite a retained claim. Restoring snapshots preserves the evidence before claims replay.

This is a historical claim about exact native property tokens. It neither proves visible appearance changed nor proves object existence, creation/removal, causal responsibility, complete request coverage or current state after later edits. In particular, changing an override from absent to explicit does not prove the rendered colour changed. Observer/receipt accuracy and semantic-to-native mapping remain trusted adapter responsibilities; self-consistent fabricated observations are not authenticated by this API. Broader predicate assessments, grouping and text realization remain separate.

assessExistenceChange(world, options)

Added with 0.195. Assesses a historical lifecycle membership transition. Load std.trace and std.reply. Required options are request, step, expectation, before, after (record IDs) and owner, revision (retained identity). Optional family, replyFamily, dry and budget have the same meaning as for assessPropertyChange. Returns {ok, created, retained?, assessment?, claim?, violations}. The claim is std.reply.existence with owner, revision and status, recomputed from immutable retained evidence whenever validated, including after restore without live trace records.

The expectation is a std.trace.presence containing source identity, source.type, scope and desired=present|absent. Each std.trace.population declares its step, invocation, before|after phase, population source/version, scope, coverage=complete|partial and semantics=lifecycle|view. Its optional repeated member references point to std.trace.subject historical source/version/source.type descriptors. Empty populations are valid; duplicate source identities are not. The step explicitly references the expectation through presence and both observations through repeated population slots. Their request, invocation, scope and population identity must agree. These additions do not alter the existing property-input contract.

Positive membership proves presence even in a partial observation; absence requires complete coverage. Unknown presence gives unconfirmed/incomplete-population. An after state that misses the desired presence gives unconfirmed/after-mismatch. Both states already matching in a lifecycle population give unchanged. A transition gives made or removed only for lifecycle populations with a confirmed step and different population revisions. A filtered view yields unconfirmed/view-membership-only: moving outside a viewport does not prove deletion. Unconfirmed execution and unchanged population revision remain explicit reasons. Inconsistent correlation refuses publication entirely.

Population semantics, completeness, authentic observations and the semantic request-to-expectation mapping are trusted host responsibilities. This mechanism does not authenticate supplied facts or establish causation against concurrent external writers. Scope must identify the same lifecycle universe in both observations; a scope label is not a query evaluator. Subject source identity must include an incarnation when native IDs can be reused. Removed objects are described by their historical before member, never by a fabricated after object. Grouping, relation predicates, numeric comparisons and request-revision linkage remain separate mechanisms.

prepareRequestBatch(input, options)

Added with 0.196. Takes {entries:[{id, request, wires, after}]} and returns {ok, plan?, issues}. Each entry carries one complete schema-valid request graph and explicitly lists the entry IDs whose semantic success it requires. Every graph is checked with the existing generic serializer and request inspector before a plan is returned. No entry can insert executable declarations or refer into another entry's graph. Graph IDs are local to an entry; the same request ID can occur in different entries without being merged.

The frozen plan contains canonical entries and topological layers. Entry and dependency IDs are sorted for reproducibility; sorting never creates a dependency. Entries in the same layer are independent. Missing dependencies, self-edges, duplicates, cycles or any malformed graph refuse the whole preparation. Existing selector/result, relation, logical group, quantifier, numeric and question structures remain intact: this boundary imposes no property-only profile and does not certify that a host implements them.

budget (default 200000) bounds batch copying, decoding and scheduling work; graphBudget (default 20000) independently bounds each graph validation. Total validation work therefore also depends on the number of entries. These are separate explicit limits, not a claimed single global operation count. Input data is copied without invoking accessors. Preparation performs no host effects and chooses no language alternative. The caller must pass an already selected interpretation and retain the reader's provenance with its journal; schema validity alone does not establish semantic coverage or user intent. Follow-up referents require explicit resolution; after does not silently bind pronouns to prior results.

A consumer may report confirmed only after its evidence establishes the required semantic success. An effect receipt or successful host call alone is not enough. evaluateRequestPredicates(world, request, options?)

Evaluates the published request predicate graph with three-valued logic. It consumes graph nodes and historical bindings; it does not read text or execute effects. Supply synchronous evaluateConstraint and resolvePopulation callbacks for the application's declared semantics. Callback truth and population coverage remain trusted inputs.

selector names a target whose selector closure should be evaluated; by default the request's result closure is evaluated. Without an explicit result root, non-selector flat constraints form a conjunction. An empty result is unknown. The callback evaluates a positive proposition; the evaluator applies the constraint's polarity and the graph's logical negations. Missing bindings, unknown leaves, incomplete populations and callback failures preserve uncertainty.

A population callback returns an explicit snapshot context, distinct historical subjects, a completeness flag and evidence. A witnessed existential can be true in an incomplete population; a witnessed counterexample can make a universal false. Exhaustive absence and universal success require complete populations. Empty complete populations follow the usual quantifier rules. The evaluator records decisions and reasons, enforces finite work/depth bounds and rejects public world mutations during evaluation. It does not publish a retained reply claim or verify the authenticity of supplied observations.

resolveRequestTargets(world, request, options?)

Selects historical subjects from explicitly declared canonical populations, using the shared predicate evaluator for selectors. policies supplies one or all per existing target; it is never inferred from surface text. Canonical kind membership, population coverage and semantic callbacks remain trusted adapter declarations.

A unique match resolves under policy one only when coverage is complete and no candidate remains unknown. Multiple known matches are ambiguous even in a partial population. Zero matches indicate absence only with complete coverage. Policy all retains known matches and resolves only with complete coverage. Structured clarification choices preserve historical instance/scope/version identity. A named target requires a declared target evaluator; matching only its kind cannot resolve its name. Result requirements never filter a target selection. New targets require creation, and bound targets remain inside lexical quantifier evaluation. No effects are performed.

budget bounds copying and revision processing; graphBudget bounds each serializer invocation independently; retentionBudget bounds retained publication. retainSelectiveCalibration(world, input, options?)

Retain an empirical selective-admission report under an immutable owner/revision. Input specifies an exact caller-declared pipeline identity, scope, explicit policy, fitRows and independent evaluationRows. Rows retain unique prediction and original source identities; duplicates across or within splits refuse. Eligible rows require finite scores and known boolean correctness labels. Ineligible rows retain null labels and remain in every coverage denominator.

Fit chooses the largest accepted cohort satisfying minFitAccepted and maxErrorRate, including all equal-score predictions together. assessSelectiveCalibration(world, reference, candidate, options?)
