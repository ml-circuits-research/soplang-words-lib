Purpose

A world is a set of SOP Lang wires (facts) that stays consistent with a matrix: a second set of wires that says which facts are possible, what follows from them, how missing values are decided, and which states are forbidden. The matrix is written in SOP Lang itself.

The world accepts wires from outside (a user turn, a sensor, another program), extends itself with what follows, and refuses what its matrix does not allow. The library is general: nothing in src/ knows a particular application.

Limits

  • Matching is indexed and starts from what changed, but partial matches are not cached (no Rete network).
  • Only deny constraints are turned into ruled-out combinations for the solvers. A conflict that arises through a rule is found when the world verifies an answer.
  • Search covers keys with a closed domain (enum, a reference type, a range). Other open keys become questions.
  • Where the matrix reads what is absent (negation, core.absent=, selectors), no value is tried on its own: the search enumerates whole assignments, and answers unknown where that proves nothing (S46).
  • Relations are linear and conclude one unknown at a time; actions written as wires have no aggregates in their calcs.
  • One justification is recorded per value; invalidation is by wire.
  • Abduction inverts add, sub, mul, div only, one unknown per calc, not through aggregates.
  • Induction is exact generalisation: it does not handle noise or learn negation.
  • A wire holds in the whole world; a fork is the only context. asOf costs a withdrawal of everything after the point asked about.
  • undo and fromJSON replay the log; fork, mark and rewind do not.
  • The budget counts steps of the library's own loops. A host function or an outside solver that loops by itself is outside it.
  • The limits of each wire type are in its entry in the reference.

How the kernel keeps its promises:

  • A change keeps a journal of undo steps; a refusal runs it backwards, so the world is exactly what it was.
  • Forks share their state; a world that changes after a fork writes on a copy-on-write layer, and the suite is run once more in a mode where any write to shared state throws (SOPWORLD_COW_CHECK=1).
  • Everything speculative (dry run, suggestion, search, abduction, supposing a wire for a query) is the ordinary change inside a transaction that is rolled back.
  • A patch, and the tells of an action, are checked where the action reads and at its end, not after each statement (S57, S59); ctx.flush() and ctx.tell(x, { now: true }) give the check after each tell.
  • The id of a derived wire is a hash of the rule and its bindings, so deriving it again gives the same id.
  • The log alone rebuilds the world.
  • world.stamp identifies the state: it changes with every committed change and is restored by a rollback, so what was computed for a state can be cached.
  • No answer of a solver is used before the world has verified it.

Build and version

npm run build writes the library as one file with no dependency at build time or at run time: docs/sopworld.mjs (ES module, browsers and Node), docs/sopworld.js (classic script with the global sopworld, and CommonJS), docs/sopworld.d.ts. npm test runs the suite on the sources and again on the built file. python3 tools/build_docs.py writes the HTML pages from the markdown.

There are no release tags. The version is version in the library and in package.json; a built file also carries build = { version, hash, date }, where hash is a fingerprint of the bundled sources. The same three are in docs/version.md, next to the built files.
