Semantic frames: one role set for every area

A reader that labels requests with the parameters of particular tools (chart.colour, node.colour, part.colour) learns the same concept once per tool, needs new labels and data for every new tool, and fails as a whole when one of hundreds of heads disagrees. A semantic frame labels what was said in a fixed, domain-general role set; the area is context, not part of a label. The capability compiler, not the reader, decides which tool and which parameter a role becomes, from declared rows (std.capability.property concept on parameter). A role no declaration takes is disclosed; the rest of the request still compiles.

The frame is plain JSON (sop.semantic-frame/1) so a neural or grammar reader can produce it. It compiles to ordinary std.request graphs, one per clause and theme, as the input of prepareRequestBatch. The optional std.request slots listed below carry the frame roles that had no slot; a graph without them reads as before.

The roles

A frame has text, optional area, optional previous ({text, frame} of the previous message), clauses and structure. Each clause has these roles. Closed banks are in FRAME_ROLES.

structure.relations lists {type: sequence | condition | instead, from, to} between clauses. Without relations, clauses run in source order, each after the previous one. Coordination needs no relation: several theme mentions in one clause share its action ("draw a cat and 2 dogs").

That is about 25 role heads, and the inventory does not grow when an area gains a tool.

Compound requests and fragments

  • Compound: one clause per request cut, with structure.relations; an anaphor across clauses names its antecedent ("Create a triangle. Move it to the right side": clause 1's mention has reference: anaphora, antecedent: {clause: 0, mention: 0}), and the compiled request of clause 1 runs after clause 0 and targets the same kind.
  • Coordination: each theme mention of a clause becomes its own request with the clause's action and the roles that name it (theme index).
  • Fragments: completeFragment(frame) completes a fragment from frame.previous.frame. A fragment with a theme of its own ("and a dog") keeps the previous action; one without ("on the lake", "bigger") applies its roles to the previous theme; replaces drops the previous role of the same concept; more and less repeat the previous attributes and motions one step further; repeats repeats the previous clause.

API

  • inspectFrame(frame, {budget?}) checks shape, banks and indices.
  • completeFragment(frame) completes fragments from the previous frame.
  • capabilityTable(world, scope) reads the std.capability declarations of one scope as a plain table.
  • bindFrame(frame, table, {budget?}) binds every role against a table: operations, kinds (declared kind labels with their canonical kind and source type), properties, repeats, objects, and, from the host, relations (source types with a placement method), amounts (named amounts with their typical count), actForms and concepts (concept aliases). A role binds only through a declared row. The result lists each role as bound (operation and parameter, placement, repeat or selector) or unbound with a reason.
  • frameToRequests(frame, {binding?, extended?, prefix?}) writes the graphs as batch entries. With a binding only bound roles are written and every other role is in disclosed with its span and reason; vague amounts are in notes. extended: false writes only the slots of the contract before version 0.237.0 and discloses the roles that need the new slots.

Limits

  • The binder decides availability from declarations; it does not execute, and a bound role can still fail at execution (a value outside a parameter's enum, a target that is not unique).
  • Modifiers stay disclosed until a reader or a kind's declared enum slots turn them into attribute concepts.
  • Motion binds only where a source type declares a position property; otherwise it is disclosed.
  • Names and codes are matched exactly against observed objects; anaphora without an antecedent takes the most recent observed object only when the frame says reference: context or anaphora.
