# General frame-to-request reader

`createGeneralEnglishReader(api)` is consumer wiring over public library mechanisms. It compiles separately scoped phrase and frame worlds, plus source-validated graph mappings from `w.reader.en.requests`. The phrase world must contain only the selected phrase overlay's structured nodes, not the older preview's competing templates. The frame world contains the frame licence/path declarations, original verb/frame/role sources, request mappings, spatial preposition sources and the spatial attribute declaration. `englishRequestMappings(api, frameWorld)` checks those mapping sources and returns detached declarations.

`reader.compile({phraseWorld, frameWorld, mappings})` checks frame source joins, compiles the grammar, and expands bounded graph profiles. It reports mapped licences and explicit unresolved licences. Call `reader.read(compiled, text)` for `{candidates, failures, coverage, interpretations, mappingSources}`. Each candidate retains the established `{request,wires,evidence,origins,coverage}` envelope. Interpretations retain the separately source-validated frame/role alternatives and their source records; they are not merged into a unique intent. Compilation is tied to the exact source worlds and their stamps.

The compiler interprets data components (`target`, `predicate`, `relation`), not verb names or acts. Selected frames supply acts. Frame roles supply explicit target modes. Neutral NP qualifiers become selection assumptions only for existing targets; on new targets they describe desired results. Result predicates remain separate. Spatial markers and goal arguments stay distinct. Exact lexical source admission prevents a fragment of a multiword preposition from being accepted merely because it shares a canonical relation with a complete preposition.

The four currently graphable published licences are creation, removal, resultative property change and spatial placement. All use the same compiler. A bare creation/removal request can have no `root` or constraints. If result constraints exist and `root` is absent, the standard contract means their implicit conjunction, excluding selector graphs; consumers must not ignore them. Native lifecycle expectations are a separate assessment contract, not invented occurrence syntax.

Before serialization, every complete parse alternative passes frame binding and source admission. Any unlicensed or ungraphable alternative refuses the reading; another supported alternative is not silently promoted to unique intent. The existing `readGrammarRequests` verifies original Unicode scalar coverage, lexical origins, exact node evidence and `inspectRequest` validity. Target evidence is retained as detached graph evidence even though targets have no source-span slots. Noncontiguous source ranges remain disjoint. The reader does not resolve native targets or execute operations.

Limits cover parse, source alignment, composition, mapping expansion and bridging. Optional read settings are only numeric budgets and parse maximums; callers cannot substitute a profile through these options. Template variants are bounded combinations of explicit determiner/qualifier states. The current consumer context reconstruction supports string-key role paths only. Numeric-index paths are explicitly refused even though the lower-level binder/projector can represent them; arrays need an exact context reconstruction contract before admission.

Increment is still unresolved because current phrase data lacks quantity/head construction and declared unit/baseline/anchor semantics. Questions, quantified NPs, coordination, dependencies and dialogue references also require source-backed constructions and bindings. There is no sentence splitting, inferred sequence, default unit or fabricated referent. When declared multi-request readings exist, their complete graph entries can feed published `prepareRequestBatch` with explicit `after` edges; this reader does not invent them. Native capability availability does not imply these language constructions are already covered.
