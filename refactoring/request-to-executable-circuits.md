# Remaining request-to-circuit work

The [book](../books/sop-worlds-teorie.md) defines the request, tool, evidence and recovery contracts. Each item below has an outstanding execution or validation check. Use the normal application route and inspect the real inputs, calls and observations in acceptance runs.

## Complete implicit and relative placement

- Apply the composition declarations in a second editor. Move a supporting object there and verify the new tool circuit uses its observed geometry. Compare an ordinary request and competing readings under the same observations. Check that changing the relation in knowledge changes both decisions without an editor-specific branch.
- Extend relative placement beyond one subject and one anchor. Compile a plural move with a bounded comparative step and a preserved property. Test attached members, independent peers and original styling. Verify every affected identity and explicitly report measurements the available geometry cannot establish.

## Compose dependent actions and read-only results

- Handle several owned targets, counts and quantitative constraints without collapsing them to one target or one action. Exercise a construction request with different counts and kinds, then change the construction through an authored world. Verify the actual allocations, relationships, observation scope and Undo.
- Compare viable readings across different interpreters under one observed revision. Use an ambiguous request with a read-only and a mutating interpretation. Verify the retained alternatives, separate admission and coverage, selected scope, and independently observed effect or absence of mutation.
- Ground natural property-value questions for a named object and for a set of objects. Verify the selected identities and reported values against a current observation. Test an unresolved property and an incomplete population without claiming a value or complete set.
- Connect declared data dependencies across editor tools. Run a current-calendar query, group its events by day, construct a chart from the typed result and insert it into a document. Verify actual queried membership and totals, result references, chart values, document content and the boundaries of the undoable operation.
- Verify recovery for dependent calls, including a changed precondition before dispatch, failure after an earlier call succeeds, and compensation that cannot restore the full state. Retain actual residual effects and distinguish stale observations, explicit refusal, search exhaustion and unknown effect.

## Complete scoped grounding and preference evidence

- Preserve source spans and alternatives for unresolved grounded names, conditions and referents. Test a known exact name against a competing kind, an anchor in a different instance, mixed positive and negative conditions, and an actually incomplete population. An unproved interpretation must remain visible.
- Carry comparable corrections into scoped preferences only under an authored learning policy. Replay a placement correction and an action-choice correction. Verify that another user, instance or comparison class receives no unrelated preference. Retraction must withdraw the contribution, and an explicit requirement must keep precedence.
- Extend capability evidence for effects that share parameter types but use different frames, reference points, or related-object scopes. Try interchangeable providers and one with an incompatible effect. Observe the selected and unaffected objects, and assert stale or incompatible input is refused before dispatch.

## Remove application-owned reasoning

- Replace the application’s explicit composition lookup in `src/dialog/composition-knowledge.mjs` and `scene-placement-defaults.mjs` with a library operation driven by declared observation and capability interfaces. Keep editor-specific extent measurement in the tool. Load a new placement relation through world declarations and exercise it through two tools without adding a JavaScript lookup.
- Audit every JavaScript component reachable from a normal editor gesture or spoken request. Identify its input SOP, output SOP and owner. Migrate remaining editor-specific interpretation, ranking, planning and default choices into schema or knowledge worlds evaluated by the generic library. Keep the reader, renderer and concrete tool boundaries visible in Worlds. Verify a policy change on the same request without changing application JavaScript and trace the resulting call through its observed effect.
- Audit the public library and tool entry points. Verify that external callers can load declared worlds and submit SOP requests, and that each mutating tool consumes only its documented SOP circuit. Remove public routes that let callers supply an internal plan or bypass the compiler with a JavaScript command object.

## Verify published application routes

- Resolve why “Delete the house” can lose its target after a question about houses. Repeat learned and authored scoped removal with two different objects in the normal published editor. Check the selected identity, retained reader evidence, exact target-bound SOP call, surviving peer and Undo. Try an ambiguous same-kind pair and a bulk operation without scoped authorization.
- Preserve the grounded target when “Are there any red houses?” follows “How many red houses are there?”. Repeat both questions before and after a real state change in the published editor. Inspect the evidence and preserve state. Include an incomplete or unsupported query and verify that the reply does not claim a complete answer.
