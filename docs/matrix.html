More of the matrix

Types that inherit, values with a kind, state that changes over time, sums over groups, questions with a status, actions, and limits on work. Each example ran as shown.

Types and kinds

A type may extend another. A pattern, a slot, a deny or a query written for the parent applies to every descendant. A slot can say what kind of literal it holds; under a key declared integer or number, 2 and 2.0 are one value.

Kinds: integer, number, boolean, string, atom, quantity.<name>, time.<name>, any. type= on a slot names the type a reference must point to. A system that already has schema wires in its own notation loads them unchanged through a core.schema.map wire; see the integration recipe.

State over time

A key can be declared a state (core.fluent) that events change (core.effect). The wire always shows the current value: the last statement, then the effects of later events, in sequence order.

core.sequence key=<key> names a key that carries the place of a wire in the sequence; without it the order of arrival is used. The checks before and after compare two wires, and a pattern with core.select=latest matches only the latest wire that fits.

Sums over a group

A calc with over= ranges over every match of a pattern: count, sum, min, max, avg, argmax, argmin, collect. The result is kept up to date as wires come and go, one group at a time.

Two helpers for patterns and templates

A template with core.on=$pattern adds its keys to the wire that pattern matched, instead of describing a wire of its own. A pattern with core.absent=<key> matches only a wire without that key; what was concluded from it is withdrawn when the key is filled.

Questions with a status, and actions

world.query answers "what is the value of this key of the thing that meets these constraints" and says how sure it is. It changes nothing.

StatusMeaning
supportedOne value (or a list, a count, a yes), with the wires and rules it came from
conflictingSeveral different values, listed as alternatives
missingNo value; the open key and the question to ask for it
refusedThe thing asked about cannot exist; the violations say why
no / unknownFor mode=exists: no when the type is declared complete, else unknown
budgetThe call ran out of steps

When no wire matches, the world supposes one with the given keys, lets the rules run, reads the value and undoes everything. That is how a rule answers "what would 3 of these cost?" without anything being recorded. A core.producer names a host function that can compute a key; a core.action names one that changes the world inside one transaction, with its required arguments and the question to ask for each.

Relations, patches, and what is only assumed

A relation states what holds among several cells, and whichever one is missing is computed, exactly. Relations feed each other within one change.

Some values are only valid together. A patch is judged as a whole: w.check(patch) tries it and undoes it, w.applyPatch(patch) keeps it, all or nothing. The search verifies whole assignments the same way.

Every value has a tier: told, derived, forced, default, guessed. What follows from others is as weak as the weakest of them. w.tier(id, key) reads it, w.assumptions() lists what is only assumed with what rests on each, a query says the tier of its answer, and a told value replaces a weaker one. w.describe() gives the whole picture as plain data, w.diff(fork) what a fork changes.

A deny or a bounded slot with soft=true refuses nothing: the change is kept and a standing core.issue wire says what is wrong for as long as it is. A query that rests on a flagged wire answers conflicting with the reason.

An action can be written as wires instead of a function: parameters, patterns, a guard, and writes that all read the state before the action.

Limits on work, and cheap copies

Every call runs under a budget of steps. A call that runs out stops, undoes what it did and says so. A fork shares the state of the original until one of the two changes, so it costs the same for any size of world.
