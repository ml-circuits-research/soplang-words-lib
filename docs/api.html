API: every public name, with what it takes and returns

import { World, parse, ... } from 'sopworld' (or from the single file docs/sopworld.mjs). This page lists everything the library exports and every public method of a world. Names that start with _ are internal and may change. The language is in language.md, the wire types in reference.md, the behaviour in semantics.md.

Conventions used on this page

  • input is SOP Lang text or an array of parsed wires.
  • A change result is { ok, added, derived, filled, merged, removed, violations }: ids of the facts added, ids of the wires rules derived, values put on existing wires ({ id, key, value, via }), facts merged into others ({ id, into }), ids removed, and the violations (empty when ok). It may also have revised (assumptions that gave way) and issues (soft violations recorded).
  • Errors. Methods do not throw for anything a matrix or a fact can cause: they return ok: false with violations. They throw SopError for text that does not parse, and Error for a call that is wrong in itself (an unknown tier, a host function that would replace a built-in). load is the exception: it throws on refusal.
  • Budget. Every method that computes takes { budget: { steps, ms } } (default 5,000,000 steps, no time limit; the world option budget changes the default). When it runs out, a change is refused with a budget violation and the world is unchanged; a reader returns what its entry says. world.stats() reports the last call.
  • Cost is given in: n facts, r rules, m matches of the bodies concerned, h statements in the log.

The examples on this page use this world:

Making a world

new World(options?)

Options, all optional: ns (the namespace of every statement of this world), facts (below), fns, actions, producers, filters (host functions by name), lemma (the host's lemma function; see register), override (let fns replace built-ins: true or names), library (module name to matrix text, for core.use), maxDepth (12), maxSteps (rule firings per change), budget, decimals, strict (refuse a change that leaves no completion), lookahead (true), solver, searchBudget, rank (reorder suggestions and explanations), vocabulary (names of the question, answer and request wires and their keys).

Properties: wires (Map of facts by id), matrix (Map of matrix wires by id), log (the statements), warnings, version, stamp, actions, producers, options. version is the token to cache by: a fork is born with its world's version, a statement that adds nothing (re-telling what the world holds), a dry run and a refused change leave it, and any change gives a version that no world of the process had before. stamp is internal (it identifies a state within one world, moves with every step of a transaction, and two forks may reuse a number for different states).

Throws if fns would replace a built-in without override. Cost: constant.

Facts the host keeps. facts: { city: (where, world) => [...] } gives the facts of a type from the host's own data (a large static table). A pattern of that type asks the provider with the values it fixes (where, keys to values, strings as their text) and matches what comes back like wires: { id, ...keys } or { id, attrs }, values as values or arrays. They are read in rules, denies, aggregates, queries and ask, are told for tiers, and are never stored, forked, logged or snapshotted. A provider must be pure and stable (the same answer for the same where for the life of the world: what a rule concluded from it is never re-examined), may return more than asked (every pattern value is checked), and should be bounded: each fact it returns costs one step of the budget, so a pattern that fixes nothing pages through the whole table under the budget. A rule needs a wire of the world to fire: a provider's facts alone start nothing. Returned facts are kept by id while the world lives. Cost: a city table of 1,000 rows takes 0.2 ms to build, against 28 ms as wires, and the snapshot is 1 kB instead of 113 kB (node bench/facts.mjs).

World.fromJSON(snapshot, options?)

Rebuilds a world from what toJSON() returned, by replaying its log. Host functions are not in a snapshot: pass the same options. Returns the world. Cost: that of telling the log again, O(h) changes; the open marks of a timeline are forks taken on the way, not replays of their own. A snapshot written with since: base is restored with { base }: the base is forked (its options and functions come with it), checked against the fingerprint in the snapshot, and only the rest is replayed.

World.audit(wires, matrix?, options?)

Checks wires that came from somewhere else against a matrix, without refusing at the first problem. Returns { ok, violations, issues, world }; world holds the wires that could be loaded. Cost: one validation of everything.

World.diff(a, b)

The same as a.diff(b).

Changing a world

world.tell(input, options?)

States wires: facts, matrix wires, or both. Options: dry (evaluate and undo), strict, tier (default told; a tier name for the whole statement, or { key: tier } for some keys, which are then assumptions that assumptions() lists and a told value replaces; a fact marked derived=true with core.source="rule <id>", as a knowledge world ships what its rules derive, has its values at the tier derived, value by value, so a merge with told values of the same identity keeps each value's origin, and why names the rule), ns (the facts go in that namespace: b1 becomes ns::b1, a reference without a namespace points into it), budget. Returns a change result. Cost: O(matches the new wires take part in) for the chase, plus validation of the touched wires; telling matrix wires recompiles the matrix and validates everything, O(n·r).

world.load(input)

tell that throws an Error when the change is refused. For matrices and fixtures, where a refusal is a mistake in the program.

world.use(name)

Loads the module name from the library; the same as telling a core.use wire. The module declares types and slots under its own name (see core.module). Returns a change result.

world.fill(id, key, value, options?)

Gives a value to a key of an existing fact. Options as for tell. A different value for a single-valued key that already has one is a conflict (use revise), except for a fluent, where it is a new statement of the state. Returns a change result.

world.revise(id, key, value, options?) and world.revise(id, values, options?)

Replaces told values, with everything that followed from them, in one transaction. Returns a change result with revised: the cells that were replaced or recomputed.

world.retract(id, options?)

Removes a told fact, the facts that refer to it, and what was derived from them alone. Refused (unknown-wire) for a wire that was not told, and when the world that remains is not valid. Returns a change result with removed. Cost: O(what depended on the wire).

world.replace(id, input, options?)

Retracts the fact id and tells input in one transaction; references to the fact stay valid when the new wire has the same id or identity. Returns a change result.

world.applyPatch(patch, options?)

Applies several changes that must hold together, all or nothing. A patch is an array of { id, key, value } fills, or { wires, fills, sets, retract, replace }: wires to tell, values to add, values to replace, ids to retract, and wires to replace in place. replace: { id, attrs } (or a list of them) gives a told wire exactly the keys in attrs (keys it had and attrs lacks are dropped) and keeps its id, so the wires that refer to it stay; what was derived from the old content is withdrawn. Options: strict, tier, budget. Returns a change result, with replaced (ids) when there were replacements. undo takes a patch back as one statement.

world.sync(collection, input, options?)

Makes a collection of told wires equal to a list, in one transaction. collection is a type (its told facts and those of its subtypes) or { prefix } (the told facts whose id starts with it); input is SOP text or parsed wires. A wire with a new id is told; one whose content differs from what was told is replaced in place (its id, and the wires that refer to it, stay); one that is the same is left alone; a wire of the collection that is not in the list is retracted. Returns the change result with told, replaced, retracted and same (ids). All or nothing. undo takes back what it told and replaced; what it retracted is not given back (use a mark). Options: strict, tier, budget. Cost: one pass over the told wires, then the patch.

With { ns } the list is told in that namespace and the collection is its part.

world.apply(assignment, options?)

Fills the values of an assignment ([{ id, key, value }], as solve returns) in one transaction. Option via names where they came from. Returns a change result.

world.undo(n = 1, options?)

Takes back the last n statements. Returns { ok, undone, removed, added, changed, violations }; nothing-to-undo when the log is empty. Statements that only touched wires of transient types are passed over and kept. A retraction is a statement like the others: undo gives the wire back. Cost: O(h) changes, since the world is rebuilt from the statements that remain.

world.redo(n = 1, options?)

Tells again what the last undo took back (or the last n undos), as the statements they were. Returns { ok, redone, removed, added, changed, violations }; nothing-to-redo when nothing was undone since the last statement that is not transient. If a statement cannot be told again, nothing is, and the world stays as it was. Cost: that of telling the statements again.

world.mark(label?), world.marks() and world.rewind(mark, options?)

mark(label) returns a point to come back to (a fork: the world's next change copies only what it touches); marks() lists the open ones, oldest first, as { label, seq, mark }. rewind(mark) makes the world exactly what it was and returns { ok, removed, added, changed }; the marks made after it are closed. A mark can be used again. rewind(mark, { only }) takes back one unit only: the told wires of a type (only: 'note') or of an id prefix (only: { prefix: 'ui.' }) become what they were at the mark, in one transaction, and everything else stays. What a rewind takes back is kept as after undo(): redo() tells it again, as one step, until the next statement (for only, the unit as it was before the rewind). toJSON({ timeline: true }) also writes the open marks and what redo would tell again, and World.fromJSON restores them, so a host that restarts keeps undo, redo and rewind; with since: base only what came after the base is written (see World.fromJSON).

world.act(request, options?)

Runs an action. request is { action, args }, a core.request wire, or its text. Returns { ok, status, value, result, missing, violations } with status done, missing (arguments to ask for), refused, error (the host function threw), unsupported (no such action) or budget.

The undo contract. One request is one undo step, and so is one sentence (an array of requests, all or nothing). Requests that carry the same options.message tag are one step together, however many calls they took, so a host that runs the clauses of one message one by one undoes them with one undo. Tags must be unique per message.

A host function gets (ctx, args). ctx.tell(input, { now }) queues a statement and returns { ok: true, queued: true }; the queue is propagated and validated together at the first read (ctx.find, ctx.val, ctx.vals, ctx.get, ctx.query, ctx.ask, any use of ctx.world), before ctx.fill, ctx.replace, ctx.retract, and at the end (S57). ctx.flush() does it now and returns the change result; { now: true } checks one tell as it is told. A refusal's violations carry queued: [{ index, ids }], the queued tells involved. Cost: one propagation for the queued tells, against one per tell (node bench/act.mjs).

One sentence, all or nothing. world.act([request, ...]) runs the requests of one sentence in turn inside one transaction: if one is not done (missing, refused, unsupported, error) none is kept, and the result says which (failed, its index), with every result so far (results) and, for a missing argument, what to ask (missing). What they did together is one step for undo and redo, also after toJSON and fromJSON. A retraction inside is undone with the rest. To know beforehand whether each request would be refused, without applying anything, give the readings to score (integration §5b).

Completing a world

world.open(id?)

The open keys (required, no value) of the world or of one wire: [{ id, type, key, ask }]. Cost: O(n), or O(keys of the wire).

world.suggest(id, key, options?)

The values that could go in a key, most plausible first: [{ value, source, count }], source being default, enum, range or wire (a wire of the slot's type). Only values the world accepts are returned; with lookahead, only values that some complete assignment contains. On budget: the array found so far, with a budget property. Cost: one trial per candidate, or one search per candidate with lookahead.

world.next(options?)

What can be done about the open keys without changing anything: { fills, questions, dead }. fills are values that are forced or defaults (kind), questions the keys that need an answer (as question wires with the options), dead the keys with no possible value. With { review: true } also review: the assumptions a host may want confirmed, weakest first; it is a pass over every value, so it is computed only when asked for. Cost: one trial per candidate of each empty slot; nothing at all when the matrix has no required slot and no default.

world.canComplete(id?)

Cheap: whether some empty slot of the world (or of one wire) has a candidate that completion could try: an optional key with a default, or a required key with a default, an enum, a range, or a type that has wires. It does not try the values, so true does not promise that complete() fills anything. For a host that completes after every change and wants to skip the call when there is nothing to look at. Cost: one pass over the wires whose type has such a slot; constant when the matrix has none.

world.complete(options?)

Applies what next found: forced values, with { defaults: true } the defaults, with { choose: true } one full solution of what is left (tier guessed). Returns { filled, questions, dead, pending }. A call on a world that has not changed since a call with the same options that filled nothing returns that answer again at once. The std.acts act complete is different: it applies what std.fill chose for a thing; the solver runs only here.

world.step(input, options?)

One turn of a dialogue: tell(input), then complete(options). Returns the change result with questions, dead and pending added.

world.answer(question, value)

Fills the key a question wire (from next, complete or step) is about. Returns a change result.

world.solve(options?), world.solveReport(options?), world.satisfiable(options?)

Search for values of all open keys that the world accepts together. Nothing changes. Options: solver, budget (the solver's own), limit (the step budget of the call). solveReport returns { status, assignment, reason, stats, solver } with status sat, unsat or unknown (S46); solve returns the assignment or null; satisfiable is false only for unsat. Cost: exponential in the number of open keys in the worst case; the default solver learns from conflicts.

world.solveAsync(options?)

solveReport for a solver that runs outside (solvers.external, dimacs, clingo with an asynchronous exec). Returns a promise of the report.

world.abduce(goal, options?)

What would have to be assumed for goal (wires, as text with ids) to hold: [{ assume, fills, text, cost }], cheapest first; empty when nothing is needed or nothing works. Options: max (10), maxDepth (3 rule steps), maxAssumptions (4). On budget: what was found, with a budget property. adopt(world, explanation) applies one.

Asking

world.ask(query, options?)

Matches patterns (text; ids may be left out) against the facts and returns the bindings, one object per match: [{ variable: value }]. A pattern's own id binds to the matched wire's id. Option at: as of that place in the sequence. On budget: the matches so far, with a budget property. Cost: O(m), using the indexes for fixed values.

With { ns } the patterns see only that namespace, and a reference without a namespace points into it. The same option on query.

world.holds(query, options?)

True when ask would return at least one match.

world.query(question, options?)

Asks for a value, with a status. question is { type, where, absent, seek, mode } or { about, seek }, a core.question wire, or its text. absent (keys) and core.absent= on a question wire match only wires with no value for those keys, as the pattern modifier does. Modes: value (default), list, count, exists, check (is where[seek], or value, the value the world has? yes, or no with actual), abduce. Options: record (tell the question and the answer as wires), suppose (default true: S53), at. Returns { status, value | values, from, via, tier, rests, wires } and, by status, alternatives, missing, reason, issues, howto, supposed, violations. The statuses are defined in semantics.

world.words() and world.interpret(frame, options?)

words() maps each text to its core.word entries, with what each means in the matrix (meanings: { kind: 'action' | 'type' | 'key' | 'value', ... }).

Order. Words keep the order in which they were told: the texts of words(), the entries of one text, the forms of one word, the readings interpret gives for a word with several meanings, the near words at one distance, and the fillers examples uses. So a host declares the most usual word first, and it comes first in examples and in ties (rank keeps the given order). The order survives forks, undo and snapshots; a word retracted and told again goes to the end.

interpret(frame) reads a frame (the host's: its tokens, lemmas, parse) into candidates for score. A frame is { verb, args, numbers, question, mode, ns }; an argument is a word or { word, role }, where role is a word for a key (with, on). A verb that means an action gives { action, args }, one that means a type gives { wires, refer } (a slot that holds a wire gets a described referent), and question: true gives { question }. An argument with no word wire is read as an entity it names by an identifying key, or an enum value spelled as is. Returns { candidates, unresolved, dropped }; each candidate also has reading (which word went where), used, unused and unresolved. Nothing is invented: every value comes from a word or a number of the frame. Options: limit (default 50 candidates), id (of the new wire, default new), near (default true).

A word that is not known (no word wire, no name, no enum value) is read as the nearest known words (a typo): within an edit distance of 1 for words of 4 letters or fewer, 2 for longer, adjacent swaps counting one; only those at the smallest distance; for the verb only words that mean an action, a type or a key. Such a candidate has assumes: [{ word, read }], which score keeps, so rank puts exact readings first and a host can say "(I read X as Y)". A known word is never corrected; near: false turns this off.

Word forms: a core.word may carry several text= forms (text=notebook text=notebooks). A token that is no known form goes through the host's lemma function, if one is registered (lemma: fn or register('lemma', fn)), before near words are tried; no language is built in.

Follow-ups ("no, a red one", "and the price?", "the other one", "tuesday then"): with { previous }, a frame with no verb or no arguments, or one the front end marks anaphor (a pronoun or "one"), correction ("no, X") or other ("the other one"), inherits the previous frame's verb, question flag and words; what it states takes the place of what the previous frame said for the same slot (a correction even in a many slot). previous is a frame, { frame, ids } (the ids the previous reading resolved to: other then describes another wire of the same type, refer.not), or 'told': the last told statement, which the frame then revises (a candidate { revise: { id, values } }, which score judges like the rest). Candidates carry inherited: { verb, words, wire } and replaced (inherited words the reading does not use). A frame with a verb and arguments and no mark is read on its own.

Loose words ("pen two buy", "red house big"): a frame { words, numbers, question } has no verb and no order. Each word that may be a verb (it means an action, a type or a key, or is near one) is tried as the verb with the others as arguments (verbWord), then each action and type that has a word as an implied verb with all the words (implied, kept when it uses one). score and rank order them by what they use; a tie at the top is the host's cue to ask. Bounded by limit and charged to the budget (site interpret; a run-out returns no candidates and budget).

One message may be several frames ("reserve the pen and order ink"). A list of frames is one split of it; a list of lists is alternative splits. Each candidate is then { parts, split }, one reading per frame (new wires new1, new2, ...), and score judges the parts in order, each on the world with the parts before it, as one whole (a frame of a split with no verb, "... and one ink", takes the verb of the frame before it and its words replace that frame's for the same slots): consistent when every part is, with the parts' lacks, assumptions and referents (each marked part) and parts, the score of each. A frame that has no reading stays as an unresolved part (unread: true, with its words in the candidate's unresolved), so a split that leaves a word out loses on words and veto reports words-left-out.

world.examples(templates?, options?)

Example sentences, generated from the tools (actions, types and keys that have words), their slots and the words; the host gives the templates, the library what fills them. templates is { action, statement, question }, each a string with {verb}, {args} and {<key>}, or a function ({ verb, args }) => string; an argument is written role word when its key has a word. Values come only from words and from names the world holds (sample per type, default 2); a number slot takes its min (or 1). Each example is { tool, text, frame, expect }: the frame a front end should give interpret for text, and the reading it should then give, so a lexicon can be tested by reading its own examples back. Options: per (default 3 a tool), all (every slot with fillers, not only the required ones), sample.

world.score(candidates, options?)

Judges candidate readings of one utterance against the world and tells nothing. A candidate is any of { wires, refer } (a statement; refer maps a reference name used in wires to { type, where, ns, not }, a description resolved against the state, not listing ids it is not), { revise: { id, values } } (a change to a told wire), { action, args, of }, or { question } (as for query).

Every scored candidate says whether it was judged and by what (judged, judgedBy): statement, action (a declared action, tried), question, or, for an action the matrix does not declare (the host carries it out), a fallback with what the matrix does know: referents (every $id argument is a wire), slots (the arguments, as keys of of, by default the type named like the action, or as type.key names, told as a wire of that type, fit their slots' kind, enum and range; required keys not given lack, with their ask), denies (no deny fires with that wire). judgedBy is the test that refused, or fallback when all that could run passed (checks lists them); with nothing to check, judged is false. veto does not report action-unavailable for a reading the fallback judged. Returns { candidates, order }; each scored candidate has ok, violations, referents ({ name, ids, unique, fits }: fits are the ids that keep the statement consistent when the description alone is ambiguous), lacks (referents nothing matches, required keys still open, missing arguments, a told subject of a question that is not there; not the value a question asks for, on a subject that is there or on a computed one the matrix has not made yet; a question may be given as an object, a core.question wire or its text), assumes (defaults the statement would rest on), action ({ available, status, missing }), answer, words (for candidates from interpret), and its place: place, why, and for a loser lostTo and on. order is best first by rank (below); option criteria replaces the default ones. See design/formalization.

PatternIndex

new PatternIndex(patterns, { normalize }) indexes a host's sentence patterns by the words they need, so its matcher tries only the patterns a sentence can match. A pattern is { id, kind, needs } plus anything of the host's (handed back as given): needs is a list of word sets, one word of each set must be in the sentence (a literal is a set of one, an alternative a set of several; leave out what is optional and the slots). A pattern that needs no word is tried on every sentence. candidates(tokens, { kind }) returns the patterns every set of which meets the sentence, in the order they were added (so a host's priority order holds); add(pattern) adds one later; stats() says { patterns, words, open, perSentence }. Each pattern is kept under its rarest set, which does not change the answer, only the work. The matching itself stays the host's; words are lowercased unless normalize says otherwise. node bench/patterns.mjs: 3,000 synthetic patterns, 1,000 sentences, 51.5 handed out per sentence instead of 3,000.

schemaCard(world, name?), schemaExamples(world, name?, options?), actReply(world, request, result)

What a host needs to read and to speak about worlds declared with std.schema, generated from the schema, in plain English (hosts translate). schemaCard gives each world (or one) as { world, doc, kinds }, each kind with its words (core.word means= the kind, else its name), acts, attrs (name, kind, values, min, max, step, default, required, refers) and limit; a world that takes any kind of a knowledge type has a kind * with open and from. schemaExamples gives sentences per act and kind with the request each should become ({ world, act, kind, text, request }; per: 2 adds a second for make). actReply gives the reply for an act from its result: what was done (with the old value, from diff), or why not and what is possible (from reason: the attributes the kind has, the kinds that have the attribute, what the kind allows and where the act works, which thing was meant). actReply(world, request, result, { templates }) writes in the host's words: a template per act and kind ('change.seat', then 'change'; for a refusal 'refused.change.seat', 'refused.change', 'refused'), a string with {thing}, {name}, {kind}, {attr}, {value}, {from}, {to}, {why}, or a function of those; with no template for the case, the plain English default. Pass it to turn as reply.

createCatalog(options) and bundleReader(bundle)

Loading knowledge worlds by lookup. createCatalog({ index, vocab, read, cache, lemma }): index.worlds lists each world's schema, depends and shards ({ id, path }), as in sop-knowledge-worlds' index.json; vocab maps a word to shard ids (vocab.json); read(path) is the host's (a file, fetch, a bundle; a promise or a text); cache is any { get, set } (a Map by default); lemma(word) gives other forms to look up (none by default). shardsOf(word) lists the shards (nothing read); plan(shards) the paths to tell, schemas of the worlds and of what they depend on first; fetch(word) reads them; into(world, word) tells them (schemas once per world) and resolves to { shards, told, ok, violations }; intoSync does the same when read answers at once. A failed read is not remembered. bundleReader({ files }) reads a bundle written by node tools/build-bundle.mjs <catalog dir> <out.json> <word|shard|world> ....

bundleThenRead(bundle, read), listOf(world, type, slot?, value?), loadBundles(world, bundles)

Knowledge readers every host needs. bundleThenRead is a read(path) for a catalog that answers from a bundled subset at once and asks read for the rest, so the first paint needs no network; .reachable() says whether the catalog answered the last time. listOf gives the names (or ids) of the loaded wires of a type, optionally those whose slot has value. loadBundles tells bundles[name] once into a world for each std.schema.world ... bundle=<name> (a world-level bundle) and returns the names told. A catalog also looks a word up once, and finds a form its vocabulary lacks through a loaded core.word (ants means ant) when given the world (into, intoSync).

createCatalogs(list, options?)

Several knowledge repositories at once, in an order of precedence: list is [{ name, index, vocab, read, cache? }] (each as createCatalog; options.lemma is shared), and the first catalog wins. shardsOf(word) gives "<name>:<shard>" from every catalog that has the word. into(world, word) tells them catalog by catalog (intoSync when every read answers at once). Each wire keeps its catalog in its source (core.source="<name>: <source>"). A wire that another catalog already told, under the same id or as a fact of the same type about the same name, is told only if it has the same values. If not, it is reported in conflicts ({ id, kept, dropped, path, keys }) and the first catalog's version stays. std.know.fill and typed needs then read what was kept.

turn(world, readings, options?)

One request, end to end. readings are the candidate readings of one message, best first: each a request { action, args }, a list of requests (one sentence), or { requests }. Each is tried on a fork (nothing changes); the first the world takes is applied as one sentence (all or nothing, one undo step) and the result has status: 'done', reading (its index), results, diff, why (the chain of each changed value), guesses (values filled by tiers, with their source) and replies (from actReply, or options.reply). Otherwise a graded fallback: ask (a reading only lacks an argument: question, missing), elsewhere (the kind is known but the act or the attribute is not here: the reply says what it can do and where), unknown (the best guess named in a question). Every result but nothing has replies (for ask and unknown, the question), and lists the readings dropped with the reason.

route(world, request, options?)

The world for a request, among the worlds declared with std.schema: each scored by its card (it has the kind, or takes any kind of a catalog: +2; it allows the act: +1), by the thing named (one of its things: +2), by a dry run (the act would be refused: −2), and by the host's own signal per world (scores, an encoder's for instance). Best first, each with the reasons: [{ world, score, why }].

schemaGrid(world, name?, options?) and gridTests(cases, options?)

The coverage grid: for every world × kind × act the schemas allow, the example request (schemaExamples) run on a copy of the world that holds one thing of each kind, with what came of it in expect: done, with the kinds added, the number removed and the keys changed; or not, with the reason (the holes are the cases not done). gridTests(cases, { importFrom, make }) writes a node:test file that runs each case again on make() (a function the host exports from importFrom) and checks it.

ledgerAppend, ledgerGroups, ledgerKey, stageOf, STAGES

A failure ledger: a failing case is data. A row is { text, world, language, happened, expected, stage, class, source, first_seen, build, was_passing }; ledgerKey is its source, text and world. ledgerAppend(rows, add) gives the rows of add that are new (old rows are never rewritten or added again). ledgerGroups(rows, { signals, examples }) groups by stage (one of STAGES: reading, routing, filling, acting, replying), class and the first of the host's cause signals ([name, row => boolean]) that holds, largest first, with examples spread over sources. stageOf(turnResult) files a failed turn. On disk: node tools/ledger.mjs add <ledger.jsonl> <rows.jsonl> and node tools/ledger.mjs report <ledger.jsonl> [--signals m.mjs] [--out r.md]. node tools/validate.mjs [--advise] <files> loads a world and lists what is refused, what is noted and the grid's holes.

turnFlow(world, readings, options?)

turn with its path declared as data (core.use world=std.turn): the stages, their order, their providers by tier and what an empty stage does are wires the application can change by telling facts (see std.turn in the reference). The providers are functions (ctx) => value (nothing yielded: undefined); the library gives given, dryrun, apply, reply, fallback, confirm (asks before an act on a whole set unless confirmed) and route (fills the world of a make); the host adds its own in providers. The result is turn's, with trace: every stage taken, its provider, what it yielded, why it yielded nothing, or why it was skipped. The declared default gives what turn gives (tested on 30 requests).

parseText(world, text, options?), grammarOf(world, options?), nounPhrase(node, cats?)

The language-free part of reading: a grammar (a knowledge world about a language) holds the language as facts — g.word text= lemma= cat= (more keys are features), g.rule lhs= rhs= ... (in order; X? optional, X* any number, X+ one or more), g.coord word= — and parseText reads text with them: every complete parse of start (default S), best first (fewer nodes, then the higher coordination), at most max (8). A node is { cat, span: [i, j], rule?, word?, lemma?, feat?, children?, coord? }; rule is the id of the rule that built it.

A grammar with names of its own says them in the options (they are the same for grammarOf): types: { rule, word, coord } renames the three fact types; classes: { DET: 'lang.det', ... } makes each wire of a closed class a word of that category (its text, its value as lemma, its other keys as features); lexicon: { word: { cat, lemma? } } is the host's open classes (nouns, adjectives: the grammar owns none); digits: 'NUM' reads digits as that category. In a rule, a lower-case or quoted part is a literal word, [all|each] is one of several, a rule with status=hole is skipped, and head= names the part the phrase is about. A text with _ (next_to) is a word of several parts, read as one token; 's is a token of its own. A left-recursive rule (NP -> NP PP) grows the phrases found so far.

The result also says tokens, unknown (the words no lexicon entry, literal or digit read: reported, never judged) and, past budget steps (20000), truncated: true with what was complete by then: it never throws. nounPhrase(node, cats) reads a noun phrase as { span, rule, quant, det, num, ord, name, pron, mods, head, lemma, pp, parts } (a coordination as { coord: [...] }; parts are the phrases inside it of the same category, such as the owner in "the house's door"); the category names are the grammar's (cats). Verbs and argument frames are next (questions.md Q32).

A grammar with its own type names, a closed class and a host lexicon:

grammarView(world, type, view?), viewDiff(world, type, a, b)

A view is the set of wires of type whose in= names it; grammarView gives their texts, sorted (every wire's without a view). Two callers that keep two lists of the same words keep two views until their owner unifies them; viewDiff says which words differ, so unifying is a measured decision.

resolve(world, phrase, options?)

The things a noun phrase names (std.schema.thing wires), and how sure the reading is. phrase is text, read with options.grammar (parseText's options, start NP) and options.cats (nounPhrase's), or a nounPhrase result. The kind is the head's lemma or a word that means it (core.word text= means=), else a kind one swap or letter away (a slip). Modifiers and a name are values of any key, and a core.word ... of=<key> word counts for that key only. A PP narrows to things with a key that refers to the one thing its noun phrase names. quant (all, each, both) and a phrase with no noun give the set. An ordinal, or a number after the noun, picks one (the id <kind><n> first); a number before the noun must be the count. A coordination is the union of its parts. A pronoun is the newest thing in focus (options.focus, ids newest first, else the std.focus.last wires that name things).

Also: a coordination whose word the grammar marks kind=choice (x.coord word=or kind=choice) is asked, never both and never the last ({ ids: [], ask: true, which }). A part without its noun borrows one: a bare number takes the noun of the part before ("tables 1 and 2"), any other part the noun of the next part ("the red or the blue house"). A coordination inside a phrase is distributed ("red and blue cups"). A part of a set (a number, quantifier or determiner with a PP and no noun: "two of the tables") is the whole set when the count covers it, else asked. A modifier that core.word maps to std.other ("the other one") keeps the things of the kind that are not in focus. A pronoun also carries guess: { word, ids }, for the host's "I took it to mean ..." sentence.

Returns { ids, tier, how }: tier is user (the words picked), scene (the only one of its kind), focus (the focus chose among several) or slip (the least sure in a coordination wins); how lists the steps, so a reply can say what it assumed. When it cannot resolve, it returns { ids: [], why, which?, kind?, unknown? }.

segment(world, text, options?) and actWords(world, extra?)

One segmenter that knows the act forms: a message cut into clauses, one act each. A joiner (options.types.joiner, default g.joiner: wires with text, cut, card_cut) cuts only when an act word starts what follows it. So "add a box and connect it to the shelf" is two clauses, while "make a cup, a plate and a bowl" and "ann, bob and cy" stay one. A run of joiners is one ("and then"). A comma right after a frame lead (options.types.frameLead, default g.frame_lead: "from now on,") never cuts. actWords gives the act words: the matrix's action names, the core.word texts that mean one, and extra (options.acts). Returns [{ text, from, to, joiner? }] (token positions). No language is built in: the joiners and leads are a language world's facts.

dialogueTurn(world, text, options?) and focusLog(world, dialogue?)

The kind of one turn, from the cue phrases the host names (std.dialogue.cue kind= text=, with core.use world=std.dialogue, or a language world's facts mapped by type in options.cues) and from the world's act words:

  • why, correction (it replaces the last act), continuation;
  • list (several things and no act), ellipsis (a thing and no act);
  • answer (a reply, when options.asked), request.

act is the action carried over from options.last, and rest is the text after the cue. A world declared modal and active (std.dialogue.modal world= active=true) is named in first: it sees the turn before the others. focusLog lists what each turn of a dialogue mentions, in order (std.focus wires). Every context hook a host registers (register('context', ...)) is copied on fork, so a dry run sees what the real run sees.

morphOf, generate, analyse, fold, splitClitics, dictionary, realise, templateFor

Morphology for language worlds (std.morph). The primitives are the same for every language and run in both directions; nothing here knows a language.

A language world declares (type names can be changed with morphOf(world, { types })):

  • paradigm classes: m.class name= parent=? drop=? alt=<from>><to>. A class inherits its parent's cells and overrides some; drop is what the lemma loses to give the stem; alt is a stem alternation, from>to, optionally anchored with @vowel (the stem's last vowel, from m.vowel text=) or @end. A cell may give its own ordered list (alt=a>ă@vowel alt=t>ț@end: several places at once) or alt=yes (the class's list).
  • cells: m.ending class= suffix= alt=yes? <feature>=<value>..., where suffix=_ means none.
  • m.irregular lemma= form= <features> (consulted first), m.fold from= to= (spelling variants, such as diacritics), m.split text= (clitic joiners) and m.template act= shape=? text= (realisation).

The functions:

  • morphOf(world) compiles these once, with a suffix index.
  • generate(m, lemma, class, features) gives a form.
  • analyse(m, form, { dictionary }) gives [{ lemma, class, features, form, exact }]. It looks up the suffix index and checks each candidate by generating it again, so no form list is stored. With a dictionary it keeps only lemmas the dictionary has, in their class, and a folded spelling finds the lemma with its diacritics.
  • dictionary({ read, prefix, fold }) is the external lexicon: one row per lemma, lemma<TAB>class<TAB>gender?<TAB>sense?, split into files by the first prefix letters and read lazily, one file when a word needs it.
  • realise(m, template, roles, { dictionary, base }) fills {role}, {role:f=v,...} (that cell) and {role@other} (agreement with another role through unification of their feature bundles).
  • splitClitics(m, word) splits a word at the clitic joiners.

arbitrate(world, request, options?)

The arbitration contract: one verdict per declared world for one request. own: the world has the kind (or the thing, or a view whose state has the attribute), allows the act, and its dry run takes it. decline: it has no use for the kind, so it declines the verb; this rule is the library's, not the host's. refuse: it has the kind, but the act is not allowed or the dry run refuses. A refusal is given only in the exact pass; in a spelling or view pass (options.pass) it stays a decline. When several worlds own, options.resolves(world, words) (a host hook, with options.words) keeps the ones whose things hold the words. Returns { verdicts: [{ world, verdict, why }], owner, ambiguous?, pass }.

needsOf(world, scope?)

The typed needs of a world or a view (std.schema.needs of= type= from=), each with whether it is loaded (some wire of its type exists): [{ of, type, from, loaded }], for { world }, { view }, or all. An act there is refused while a need is not loaded (reason.needs); turn(world, readings, { load }) calls load(need, world) for each and dry-runs again, and says what it loaded.

rank(scored, criteria?) and RANKING

Orders scored readings best first and explains every place. RANKING is the default list of criteria, each { name, measure, say } (lower measure is better): consistent, referents (how many are left ambiguous), lacks, words (words of the frame left out), assumes; ties keep the given order. Returns { order, ranked }; ranked[i] is { index, place, why, lostTo, on }: the first says what it satisfies, any other names the first criterion on which the winner is better and what each is on it, a tie says so. A host may put its own criteria before, after or instead of these.

world.veto(result, options?) and veto(result, options?)

Whether a host should answer with the top reading of score, or say "not understood" or ask. Returns { answer, index, reasons, ask, read }; answer is false when any reason is given, each { reason, why }: nothing (no reading), inconsistent (the top reading breaks the world, a refusing guard included), no-referent, ambiguous (a referent still open), action-unavailable (an action the world does not have), words-left-out (more than leftOut, default 0), too-few-words (fewer than minWords, default 1), tie (the next reading is as good on every criterion). ask lists what the reading lacks with its question, for a host that asks instead of answering; read lists the words read as near known ones. Options: minWords, leftOut, criteria.

world.get(id), world.has(id), world.resolve(id), world.ofType(type)

get returns the fact { id, type, attrs, meta } or undefined; attrs maps each key to an array of values. has says whether it exists. resolve returns the id of the wire that an id names now (after a merge), or the id itself. ofType returns the facts of a type and of its subtypes. Do not modify what they return. Cost: constant; ofType O(result).

world.schema(type)

What the matrix says about a type: { type, extends, lineage, closed, keys }, each key with its slot's attributes and inherited; null for a type the matrix does not mention.

world.explain(id)

Where a wire comes from: { id, wire, tier, told, via, from, fills }: the wire as text, whether it was told, else the rule (via) that derived it, the wires it was derived from (each explained in turn), and the values that were added to it later (fills, each with key, value, via, from); null for an unknown id.

Advice at load (advise)

new World({ advise: true }): when the matrix is loaded, world.warnings gets advice (kind advice, never an error) for an author: a kind of the application with the shape of a kind of an imported module ("kind card here has the shape of shapes.box in module shapes: import it?"), and a rule with the shape of a rule of another module, such as the standard pack ("the rule mine is already in std.relations (std.relations.slotted)"). Off by default. The study behind it is patterns; tools/reuse.mjs does the same across whole worlds.

world.why(id, key?)

Why a wire, or one of its values, is what it is, in one structure a host turns into a sentence ("why is it so low?", "why did you open chess?"): { id, key, steps }, the steps from the cell asked about back to what was told, each wire once, depth first in the order the rules read them. A step is { id, key, value } (or wire, its text, for a whole wire), its tier, and how: told; action (told or set by the action named in action); rule (with rule and the wires it read, from); aggregate (a group result); default (a slot default); open (no value). A std.fill need that was filled says its choice ({ key, value, tier, source }) and goes on through the offer chosen. null for an unknown id. explain gives the same as a tree, for one wire.

world.tier(id, key?) and world.assumptions(ids?)

tier is the certainty of a cell, or of a wire as a whole: told, derived, forced, default, guessed or a declared tier; undefined when there is no such cell. assumptions() lists every cell weaker than derived, weakest first: [{ id, key, value, tier, dependants }]; assumptions(ids) only what those wires rest on, with dependants among them, without a pass over the world.

world.told()

The facts as they were stated, without what rules, defaults and searches added: an array of wires that can be told to another world.

world.describe(options?) and world.diff(other)

describe returns a summary as plain data: { types, wires, open, assumed, issues, changes }. Options: about (one wire and what is within depth references of it), since (changes after that sequence number), last (20 changes). diff returns what is different in another world: { same, added, removed, changed }. Cost: O(n).

world.check(patch?, options?)

With a patch: what applyPatch(patch) would return, without changing anything. Without one: validates the whole world and returns { ok, violations, issues }.

With { query } or { ask } (a question for query, patterns for ask) the patch is applied in a transaction that is then undone, and the result also has answer (what query gives on the world with the patch) or rows (what ask gives there). The same from the other side: query(q, { given: patch }) and ask(patterns, { given: patch }) answer on the world as it would be with the patch; a patch the world refuses gives the status refused with the violations. Nothing changes. The questions are asked in the patch's namespace (ns, or the world's). A patch may also be SOP text: its wires.

Worlds, time and history

world.fork()

An independent world with the same content. Nothing is copied: each of the two worlds, at its first change, puts a copy-on-write layer over what they share and writes there, so a change after a fork copies only the wires and index entries it touches. Cost: constant; the first change after it costs about what the same change costs without a fork, whatever the size of the world (node bench/fork.mjs).

world.trial(fn, options?)

Runs fn(world) and undoes whatever it changed; returns what fn returned, or undefined on budget. For what-if questions without a fork.

world.asOf(at, fn, options?), world.seqOf(id), world.compare(idA, idB)

seqOf is the place of a wire in the sequence. compare is negative when the first wire comes before the second, positive when after. asOf runs fn against the world as it was at place at and returns its result; the world is unchanged. Cost of asOf: O(wires after at).

world.history() and world.on(listener)

history() returns the committed events, oldest first: [{ seq, op, ... }]. on(listener) calls listener(events, world) after every committed change and returns a function that stops it.

world.toSOP(options?) and world.toJSON()

toSOP writes the facts as text, in order of arrival. Options: schema (the matrix too), derived (true; false leaves out derived wires), provenance (add core.via and core.from). toJSON returns { format: 'sopworld', version, log }, for World.fromJSON. Options: timeline (also the open marks and the redo stack; a mark on the way of the log is its position at, any other its own log), since (a world this one grew from, such as the one it was forked from: only the entries after that world's log are written, with base: { length, last }, a fingerprint).

world.register(kind, name, fn, options?)

Adds a host function after the world was made. Declare it in the matrix too (core.function, see the reference): a registered function with no declaration still works, with an undeclared-function note. kind is function ((args, world) => value, for calcs, checks and effects), action ((context, args) => value), producer ((context) => value), filter ((value, { world, name }) => text, for ?v:name in a reason), context (a host hook such as the session's facts, read by the host's actions as ctx.world.context.<name>; no matrix names it) or lemma, given as register('lemma', fn) with no name ((token) => form | forms: the dictionary forms of a token that is not a known word, for interpret; it must be pure and know nothing of the world). A function with the name of a built-in throws unless { override: true }. Returns the world.

world.modules()

The modules of the matrix, in order: { name, version, imports, exports } (version and exports when the module declares them).

world.functions()

The host functions the matrix declares, in order: { name, out: { kind }, pure, doc, args: [{ name, kind, optional, doc }], registered }. A reader derives its tool descriptions from them.

world.cannot(reason)

For host functions: say why there is no result, before returning nothing. A query that supposed a wire and needed the result answers unsupported with that reason.

world.stats()

The cost of the last call: { steps, limit, exhausted, site, sites, ms }, sites giving the steps per place (match, chase, negation, aggregate, fluent, withdraw, validate, complete, ground, solve, abduce, induce, interpret).

Functions

parse(text, options?), tokenize(text, options?)

parse returns the wires of a text: [{ id, type, attrs, pattern }], attrs mapping each key to the array of its value tokens. Options: anonymous (a declaration may leave out its @id, for queries), lenient (read what versions before 0.6.1 read: an id twice in one text, escapes JSON does not have, a quote or backslash in an atom). It throws SopError listing every error of the text (the list). tokenize returns the tokens: [{ t, line, column, offset }]. Cost: linear in the text.

format(wire, options?) and serialize(wires, options?)

format writes one wire: on one line; with { multiline: true } one entry per line; with { canonical: true } in the canonical form (entries sorted by key, strings in one spelling). serialize writes several wires, each followed by a line end, with the same options; serialize(wires, { canonical: true }) gives the same bytes for the same wires.

str(value), quote(text), readValue(token), writeValue(value)

str gives the text of a string token (escapes decoded) and returns any other value unchanged; quote gives the string token of a text, in the canonical spelling (the escapes of JSON). readValue gives a token as data, { kind, v } with kind atom, string, ref or var; writeValue is its inverse (and throws for another kind). They are what a host with its own parser needs to hand over wires.

SopError

What parse, tell and the other methods throw for text that is not SOP Lang. It has message, line, column and offset of the first error, and errors: every error of the text as { message, offset, line, column }.

unify(a, b, bindings?) and walk(term, bindings)

unify matches two values (an atom, a ?variable, a $reference, also $?variable) and returns the bindings, extended from those given, or null when they cannot be the same. walk returns what a value stands for under bindings.

abduce(world, goal, options?) and adopt(world, explanation)

abduce is world.abduce. adopt tells an explanation's wires and fills (tier guessed) and returns { ok, results }.

induce(examples, options?), induceRule(examples, options?), induceSlots(wires, options?)

induce generalises examples ([{ when, then }], text or wires) into one rule, or with { kind: 'deny' } into a deny: { text, calcs, tests, skipped, coversNegative, variables, examples }. Options: name, why, tolerant (skip examples of another shape), negatives, budget. induceRule returns only the text. induceSlots proposes slots for observed wires. What they return is text to review and tell.

quantity(value)

Reads a number with an optional unit: { n, unit }, or null.

solvers, Problem, Sat, toDimacs(data), toASP(data)

solvers.cdcl() (the default) and solvers.backtrack() are built in. solvers.external({ run }), solvers.dimacs({ exec }) and solvers.clingo({ exec }) hand the problem to a program outside; what it proposes is verified by the world. new Problem(world) is the search problem of a world (variables, nogoods, verify, toJSON); toDimacs and toASP write it for a SAT or an ASP solver. Sat is the built-in SAT solver (addClause, solve, model).

builtins, aggregates, GRAMMAR, MODIFIERS, SCHEMA_TYPES

Tables, for tools: the built-in functions and aggregates by name; for each matrix wire type the attributes it reads (GRAMMAR; a name that ends in . is a prefix); the attributes that may stand on any pattern or template (MODIFIERS); the types that make a wire a matrix wire (SCHEMA_TYPES).
