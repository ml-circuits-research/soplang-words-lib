Glossary

One line per term. These words are used with these meanings in every document, in the code and in the messages of the library.

TermMeaning
wireOne declaration: @id type key=value .... The unit of everything.
circuitWires connected by references.
factA wire that says something is so. It has no variables.
matrixThe wires that say which facts may exist and what follows from them: slots, types, rules, denies and the rest. Short for consistency matrix.
patternA matrix wire that describes wires to find. Named by when=, not=, over=, remove=, or given to ask.
templateA matrix wire that describes a wire to make or to complete. Named by then=, set=, add=.
variable?name in value position: a value to be found by matching.
reference$id in value position: another wire.
worldA set of facts kept consistent with a matrix: the object the library gives you (new World()). What it holds is one of the three kinds of worlds below, usually a live world.
stateEverything a world holds at one moment. Also: a value that changes over time (see fluent).
forkA second world that starts as a copy of the first. Also called a scenario when it is used to try something.
markA point in the life of a world that it can be rewound to.
typeThe second token of a wire. A type may extend another.
slotThe declaration of one key of one type: what it may hold, whether it is required.
kindWhat sort of literal a slot holds: integer, number, boolean, string, atom, quantity.<name>, time.<name>, any.
open keyA required key that has no value yet. An open key is a question.
identity keyA key that says which thing a wire is about (id=true). Two wires with the same identity keys are one wire.
rule"If these patterns match, these templates hold."
deny"These patterns must not match."
calcA value computed by a named function inside a rule.
checkA condition computed by a named function inside a rule or deny.
aggregateA calc that ranges over all matches of a pattern: count, sum, the largest.
relationA statement that holds among several values, from which whichever is missing is computed.
sequenceThe order of wires in time: by a declared key, else by arrival.
fluentA key whose value is a state that events change.
eventA fact that changes a fluent through an effect.
effectThe declaration of how one type of event changes one fluent.
derivedMade or filled by a rule, a relation or an effect, not told.
provenanceWhere a wire or value comes from: via (which rule), from (which wires), cells (which values).
cellOne value: a wire id and a key.
tierHow solid a value is: told, derived, forced, default, guessed, or a tier the matrix declares.
assumptionA value weaker than derived: something the world took, not something it was told or proved.
defaultThe value a slot offers when nobody gave one. Taken as an assumption.
transactionOne change, applied whole or not at all.
patchSeveral changes judged and applied together.
chaseRunning the rules until nothing new follows.
violationThe reason a change was refused, as data.
issueA violation of a soft constraint, kept in the world as a core.issue wire while it lasts.
softSaid of a deny or a bound that records an issue instead of refusing.
queryA question with a status in the answer: world.query.
statusHow sure an answer is: supported, conflicting, ambiguous, missing, refused, unsupported, no, unknown, budget.
suppositionA wire the world tells itself to answer a query, and takes back.
actionAn operation that changes the world on request, as a function or written as wires.
producerA host function that computes a key when it is asked for.
functionA named piece of host or built-in code that a calc or check calls.
completionFilling open keys: by rules, by forced values, by defaults, by choice.
domainThe values an open key may take, when they can be listed.
searchFinding values for all open keys with a listable domain at once.
solverThe strategy a search uses.
abductionFinding what would have to be true for something to hold.
abducibleDeclared as something that may be assumed in an abduction.
inductionFinding a rule or slots that explain examples.
budgetThe number of steps a call may take.
moduleA matrix kept in the library under a name and loaded with core.use.
buildThe single file made from the sources; it knows its version and fingerprint.

The three kinds of worlds

One name per kind, used in every document and in the repositories around the library (sop-knowledge-worlds, the applications). In Romanian: schema lumii, lume de cunoaștere, lume vie.

KindWhat it isExampleWhere it lives
world schemaWhat a kind of world is: its kinds of things, their attributes and value types, the acts that apply, limits, rules and the words for them. No particular things. Reusable.a seating plan: tables, seats and guests, at most 50 tables, make, change, connectsop-knowledge-worlds, as w.* (w.seating, w.timeline, w.list); written with std.schema
knowledge worldFacts about the world at large, true for everyone, with no session state.animals, places, colours, units; w.lang.en is a knowledge world about a languagesop-knowledge-worlds, as k.* (and w.lang.en); read with createCatalog, std.know
live worldOne running instance of a world schema in a session: the things the user made, their current values, the focus, the history and undo. Temporary and particular. It follows its schema and reads knowledge worlds.the plan for Saturday's dinner: table 1 is round, Ann sits at seat 2, undo gives back the table just removedthe application's session, in one World object

What each kind may contain, and where code lives: kinds of worlds.

How they relate: a live world = world schemas + the knowledge worlds it reads + session state. A host loads one or more world schemas (core.use, or the published text) and what it needs of the knowledge worlds (createCatalog, std.schema.needs) into a World. The acts of the user then make it a live world. A view is how an application shows a live world (a tab, a floor plan, a map): it shows some aspects of the same things (std.schema.view) and may have attributes of its own (state=).

Library modules (std.*: std.schema, std.acts, std.fill, std.focus, std.relations, std.know, std.turn; and the grammar reader) are mechanisms, not worlds. A world schema is written with them, and a live world runs on them.
